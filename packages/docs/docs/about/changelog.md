# Changelog

## Recent Changes

Entries from June 2026 onward are grouped by release so you can map them to the version you are running — check yours with `chaoscypher --version` (CLI) or the container image tag.

### October 2026

#### v0.6.0 (2026-10-27)

The agent-memory release — 176 changes landed since v0.5.0, 125 of them in the shipped tree. Three themes. Memory for agents: five MCP tools let an agent remember a sentence and recall it later as facts with their sources, in a mode that needs no embedding model, with several processes writing one database and memories that could not be linked yet kept and linked later. Retrieval that reads the question: chat retrieval sorts each question by shape, hands the model a tighter graph context with the sentences behind it, merges one entity written under two names, and hybrid search gains a real keyword half. And sources you can keep current: a whole documentation site imports as one site and checks itself for updates. Eighteen migrations (`0008`–`0025`), six of them `needs_confirmation`, and several breaking changes for MCP clients, custom domain plugins and databases from before the core entity types — read **Breaking changes** and **Upgrade advisory** before you upgrade.

##### Breaking changes

- **BREAKING: databases from before the core entity types are not migrated in place.** A graph extracted before this version keeps its old type names (`Character`, `Military Unit`) and its per-type templates; it still opens, nothing is rewritten, and the dashboard (and `GET /api/v1/databases/current`, as `notice`) says so in one line, with one `database_predates_core_types` warning per database in the log. To move it onto the core types: **export it with the previous version, update, then import the export** into a new database. The import maps the old types: each node is stored under its core type with the old name as its `entity_subtype` (read with the packs its sources were extracted with), a name the mapping table does not hold is kept as a `Concept` flagged `unplaced_type`, the old per-type node templates give way to one template per core type, and relationships are imported unchanged. The import's result lists what it mapped, old type by old type (`core_types_mapped`, also in the job result, the CLI's import table and the `ccx_import_core_types_mapped` log line). See [Upgrading](../getting-started/upgrading.md#databases-from-before-the-core-entity-types).
- **BREAKING: custom domain plugins must be converted to packs.** A domain `.jsonld` written for 0.5.0 (its own node templates, no `role`) is refused at load and logged as `domain_schema_invalid`, so it no longer takes part in detection or extraction. A pack declares `"role": "pack"` and `"extends": "core"` and may only add subtypes of the eight core types, relationship labels and prompts; it is refused if it declares node templates, a core label, a limit below the floor's, `strict_entity_types` or a removed key (`guidance`, `entity_templates`, `strict_validation`, `normalizer_overrides`, `allow_template_fallback`, `extraction_overrides`, `vocabulary_exclusions`, `evidence_validation_mode`). To convert one, run `python -m chaoscypher_core.services.sources.engine.extraction.domains.convert_packs --write my.jsonld` (without `--write` it reports what it would change); it maps every old template name onto its core type. See [Building Domains](../developer-guide/building-domains.md).
- **BREAKING: a failed MCP or chat tool call answers a fixed sentence and a `code`, never the error's own text.** Graph tools answer `{"success": false, "error": "Not done: …", "code": "…"}` with `code` one of `UNKNOWN_TEMPLATE`, `AMBIGUOUS_TEMPLATE`, `UNKNOWN_NODE`, `MISSING_REFERENCE`, `DUPLICATE`, `INVALID_INPUT`, `NOT_FOUND`, `DATABASE_BUSY` or `OPERATION_FAILED`; the memory and site tools give the sentence alone, marked as an error; and a failed MCP tool call now sets `isError: true`. In 0.5.0 a failure answered `Operation failed` or `Tool execution failed` (the workflow executor with no `success` key), and an exception that escaped a tool reached the client as raw text that could quote the SQL and its values. A client that matched those strings, or relied on `isError` staying false, should branch on `code` instead.
- **BREAKING: the MCP server runs only the tools it advertises, in write mode too.** A client could call a handler that is in no tool list (`summarize`, `research_topic`) and the write-mode server ran it; an unlisted name now answers `UNKNOWN_TOOL`. Read mode still answers `NOT_AUTHORIZED` for write-only tools. A request to `/api/v1/mcp` that did not come through nginx now gets the shared `AUTH_REQUIRED` 401 envelope instead of `{"error": "authentication_required"}`.
- **BREAKING: the sources API refuses bad extraction options up front (422).** `analysis_depth` must be `quick` or `full` on URL import, upload, trigger and confirm — a value such as `deep` used to be accepted with a 202 and fail in the worker, after a forced re-extract had already deleted the source's graph. `max_entity_degree_override` must be a positive integer everywhere, and `GET /api/v1/sources?enabled=` takes only `enabled` or `disabled`.
- **BREAKING: with vector search off, anything that needs vectors is refused instead of loading a model.** Under `search.enable_vector_search: false`, semantic search, the Python API's embed helpers and the generate-embedding tool raise `VectorSearchOff`, whose message says keyword search still works. Turn vector search on, or use keyword or hybrid search (hybrid answers with its keyword results).
- **BREAKING: a hybrid search `score` is now a fused rank score.** `search_type=hybrid` merges a keyword search over nodes, one over chunks and a semantic search by reciprocal rank, scaled so a result ranked first in every list scores 1.0; it used to keep each result's higher raw BM25 or cosine score. Result order changes, and a client that thresholds hybrid `score` against a BM25 or cosine value must pick a new threshold. Keyword and semantic searches keep their own scores.
- **BREAKING: `chaoscypher compose build` replaces the composed database by default.** It used to upsert onto the previous build unless you passed `--clean`, so entities from a package you had removed from `axiomatize.yaml` kept being served. The option is now `--clean/--no-clean`, on by default; pass `--no-clean` to add to the existing build. The summary prints `Clean build: Yes` or `No (upsert)`. A `--no-clean` build now never loses the composition it started from (see **Reliability**).
- **BREAKING: the strict address policy refuses every address that is not globally routable**, including shared and CGNAT space (`100.64.0.0/10`). URL imports, site crawls, web-search fetches, the workflow HTTP request step and Lexicon URLs pointed at such an address are now refused. See **Security** for the address-spelling fixes that came with it.
- **BREAKING: `chaoscypher benchmark reference export` requires `--dedup-embedder`** (the embedder whose vectors merged the graph's entities, or `exact`). Scripts that call it as in 0.5.0 must add the flag.

##### Features

- **Agent memory: `remember`, `recall`, `forget`, `list_memories` and `digest`.** Five new MCP tools let an agent hand ChaosCypher a sentence or a note in plain words and later get it back as facts with where they came from.
  - `remember(text, by?, scope?, valid_from?, about?)` stores the text as a source of type `memory`: kept whole and searchable at once, its facts extracted against the entities the graph already knows, so a later "Pierre" lands on the same Pierre node. A text that looks like a key or a password is refused and nothing is stored; a text with no facts in it is kept as a note.
  - `recall(query, scope?, as_of?, more?, ids?)` answers in the shape of the question — an entity card, a grouped list, a relation chain, or the digest for a broad question — with every fact tagged `[who DATE]`, `[doc TITLE]` or `[pack NAME]`. Documents and packs are always in scope, and up to three of their own passages come back under `Passages:` (cut at 320 characters), so a question about a manual gets the manual's words even where no fact was extracted.
  - A later memory on a single-valued relation (where someone lives) replaces the earlier fact and keeps it as history; `recall(as_of=…)` shows the facts as they stood on a date.
  - `forget` first previews the matches, each with a handle; `forget(handle=…, confirm=true)` then removes that one memory and the facts only it stated, reopens what it had replaced, and leaves an audit row with the handle, who and the counts — never the text.
  - `digest(scope?, since?)` says what a window added, replaced and forgot. Every answer is plain text, cut to `mcp.memory.result_chars` (default `1600`); `mcp.memory.default_by` (default `user`) names who said it when the caller does not. See [Memory](../user-guide/memory.md).
- **Tool profiles: `chaoscypher mcp --profile memory` serves only the five memory tools.** New settings `mcp.profile` (`full`, the default, or `memory`) and `mcp.tools` (an allowlist that narrows the profile, empty by default) keep a small model's tool list short. A name that is not a registered tool, or an allowlisted tool outside the profile, is a configuration error named at start.
- **Memory packs: `chaoscypher memory export`.** `chaoscypher memory export [--scope S] [--title T] OUTPUT.ccx` writes one scope's memories (every memory without `--scope`) with the facts they link, the sentences that state them and what each replaced; the title defaults to `memory:SCOPE`. `chaoscypher graph package load` brings them back as memories with their `by`, scope and date, so they can be recalled, replaced and forgotten in the other database too.
- **A keyword-only mode that loads no embedding model.** With `search.enable_vector_search: false` (or `CHAOSCYPHER_SEARCH__ENABLE_VECTOR_SEARCH=false`) the CLI, the Python API and `chaoscypher mcp` make no embedding call for searches or writes: hybrid search answers with its keyword results, writes are stored and keyword-indexed without vectors, entities merge by name, and every memory tool works. A keyword-only process never changes the vector tables, so it can share a database with one that has vector search on. After turning vectors back on, `chaoscypher source rebuild-search --embed-missing` embeds only the chunks and nodes written in the meantime.
- **A memory that cannot be linked yet is kept, says why, and links later.** `remember` stores the memory before it links it into the graph. If linking does not finish within `mcp.memory.wait_seconds` — default `20` seconds (it was `120` on `main` before this release) — the answer's second line says why: the model did not answer in time, the model failed, or no extraction model is set up. Until it links, the memory is a note: `recall` shows it under `Notes:`, `forget` can remove it, `list_memories` ends its line with its state and `digest` counts the memories not linked yet. A write-mode server links pending memories in the background once the client has connected, oldest first (`mcp.memory.relink_on_start`, default `true`); `chaoscypher memory relink` does the same on demand (see **CLI**). A memory whose link keeps failing waits longer after each failure, never more than a day, and is never dropped.
- **Scoped memories link to what their scope is about.** Before extraction, a memory with a `scope` is shown the nodes its scope's other memories name most, plus the nodes listed for that scope in `mcp.memory.scope_nodes` (scope name to node labels, default empty), within `extraction.known_entities_limit`. A scoped memory that writes the exact name of a node a person made, offered by its scope, is attached to that node, which keeps its own name, type and properties. It may also use the templates its scope's nodes use and those named in `mcp.memory.scope_templates` (default empty) — only templates a person made, never a built-in one or one an import owns — and forgetting a memory never deletes such a template. Memories without a scope, and every document, behave as before; a configured name that matches nothing is skipped and logged once.
- **Several processes can write one memory database at once.** One `chaoscypher mcp -m write` per agent, `chaoscypher` commands and timers that run them can share a database on the same machine and a local disk (network filesystems are not supported). A memory links whole or not at all, no write is lost, the graph settles as if the calls had taken turns, and every tool call reads fresh rows, so a long-running server sees what another process just saved. Each write waits up to 60 seconds for the writer lock; a write that still cannot land answers one fixed line and never hangs — `Not stored: the database is busy. Try again.` from `remember`, `Not done: the database is busy with another process's write. Try again.` (code `DATABASE_BUSY`) from the other tools. Several servers can start at once on a database that does not exist yet: the first builds it and the others wait.
- **New MCP read tool `list_nodes`.** It lists every node, or one template's nodes by template id or name, paged by `skip` and `limit`, without a search query.
- **Import a whole documentation site from one address.** Paste a docs site's URL and each of its pages is imported as its own source under one site; citations link the page they came from, and the site shows as one row with one progress bar. Pages are found the first way that works — the site's `llms.txt`, then its sitemaps, then a crawl three links deep — and the import never leaves the address's scheme, host and path. **Add Source** checks a pasted URL once you stop typing and offers **Import the whole site: N pages** or **Just this page** (the default); **Show pages** lets you untick pages first. Also `chaoscypher source add URL --site` (`--yes` skips the prompt), the write-mode MCP tool `add_site(url)`, and `POST /api/v1/sources/sites/previews` (a dry run) then `POST /api/v1/sources/sites` (202; a scope already imported answers 409 with the existing site in `details.site`). See [Import a Docs Site](../user-guide/site-import.md).
- **Check a site for updates, and manage imported sites.** **Check for updates** re-fetches every page: an unchanged page is left alone, a changed one re-imported in place, a new one added, and a page the site no longer lists is marked **Gone from site**, never deleted. An interrupted run resumes where it stopped; a site whose worker died is marked **Failed**; **Delete site** keeps the pages as ordinary sources unless you ask otherwise. CLI: `chaoscypher source site list | show | refresh | delete`; MCP: `refresh_site(site)`; API: `GET /api/v1/sources/sites`, `GET /api/v1/sources/sites/{id}`, `GET /api/v1/sources/sites/{id}/pages`, `POST /api/v1/sources/sites/{id}/refreshes` and `DELETE /api/v1/sources/sites/{id}`, and `GET /api/v1/sources` gains `in_site`.
- **A site remembers the pages you left out.** Pages you untick at import, or later delete from the site, stay out of every update check (shown as **Left out**; the site row says **N pages left out** and **Include the left-out pages** brings them back), while a page the site gains later is still added. `source site refresh --exclude URL` (repeatable) replaces the list and `--include-all` empties it; `refresh_site` and the refreshes endpoint take `exclude` (`[]` brings every page back). An entry that names no page of the site is refused with a 400.
- **Site crawling is polite and configurable in the `web` group.** Every web request (URL imports, web search, the crawler) now sends `web.user_agent` (default `ChaosCypher/<version> (+https://chaoscypher.com)`) and honours `robots.txt` (`web.respect_robots_txt`), with a crawl delay (`web.crawl_delay_seconds` 0.5, at most `web.crawl_delay_max_seconds` 5), `web.crawl_concurrency` 2, and limits on pages (`web.site_max_pages` 500), depth, sitemaps, document size and run time, plus preview limits. Every address and redirect hop passes the strict address check.
- **Chat retrieval reads the question's shape.** Before it builds the graph context, `graphrag_search` decides whether a question is a `lookup`, an `aggregate` (everything sharing a relation with a named entity), a `path` (how two named things are connected) or `global`. An aggregate question gets the entity's relationships grouped by label, each with the sentence that states it (`graphrag.aggregate_per_label`, 12); a path question gets the shortest relation chains between the two entities across the whole graph, each hop with its sentence, or a line saying none was found (`graphrag.max_hops` 3, `graphrag.max_walks` 6); and the chunks those lines cite enter the chunk budget by right (`graphrag.evidence_chunks`). `graphrag.router` decides the shape: `rules` (the default) from the named entities and cue words with no extra model call, `rules_then_llm` asks the chat model one short question when the rules cannot decide, `llm` always asks, `off` treats every question as a lookup. In chat, the `graphrag_search` tool item shows the shape and the lines the model read. See [Search](../user-guide/search.md).
- **An identity resolver merges one entity written under two names.** After every commit (`graph.resolve_identities`, on by default), two nodes of one core type are merged when one's name is the other's alias, or is the other's name with words left out and nothing added — the rule extraction's deduplication now uses too. A two-word alias that names exactly one other node is moved off, and a family relationship whose justification names someone other than its two ends is flagged with `resolution_flag`, never deleted. Edges move with their provenance and the touched nodes are re-embedded. The `graph` section is now settable in `settings.yaml`.
- **Extraction shows each passage the entities earlier passages named.** From a source's second group on, the extraction prompt carries a KNOWN ENTITIES block — name, core type, aliases and up to three relation phrases — so a later "the count" or "the regiment" no longer becomes a separate node. At most `extraction.known_entities_limit` lines (new, default `80`, `0` turns it off). Two guards come with it: an alias that is another listed entity's name is taken off the record (kept as `properties.alias_crossed_known`), and a listed name the cited sentences never write is demoted to the phrase they do write or flagged `referent_unevidenced`. The source page counts both ("Crossed aliases", "Demoted or flagged names"; migration `0018`). On the queue worker, where groups run in parallel, the block a passage sees can depend on which earlier groups have finished.
- **Lever profiles bind GraphRAG settings to a chat model.** `graphrag.profiles` holds named bundles of `graphrag` values and `graphrag.profile_rules` says which bundle a chat model gets — by exact `model`, by parameter-size band or by corpus `domain`, first match wins. Both are empty by default.
- **A two-part question can be searched one part at a time** (`graphrag.question_parts`, off by default). With it on, the chunk search also runs once per part of a question such as "Who is X's father, and what did Y tell Z?" and merges the hits by rank.
- **An LLM response and embedding cache, with a Cache section on the Settings page.** Pinned completions (temperature 0, plus a seed on Ollama) and every embedding are kept on disk under `<data_dir>/cache/llm`, keyed on the exact model build, the messages, the decoding and the tools, so re-importing a document, retrying an extraction or asking the same grounded question again is answered without the model. Sampled decoding (a raised temperature, a regeneration) is never cached, nor is an answer cut off by the loop guard, the token limit or an error; a hosted provider's answer is cached as the first answer seen, flagged unseeded, because hosted models ignore the seed. Both caches are on by default with a 2 GB cap each and least-recently-used eviction, configured in the new `cache:` section of `settings.yaml`. **Settings → General → Cache** shows each cache's entries, size against the cap, hit rate and time saved, split by call site, with an enable switch that applies at once and a Clear button; the same is available as `GET /api/v1/cache`, `PATCH /api/v1/cache` and `POST /api/v1/cache/{name}/clear`. In Core, `CachedChatProvider` and `CachedEmbeddingProvider` wrap any provider around a `SqliteCacheStore`. New pages: Getting Started → Cache, and the Cache API reference.

##### Behavior changes

- **The graph is handed to the chat model in a new shape.** New `graphrag` defaults: `max_triples` `40` (was `200`), keeping the `connected` edges between the top PageRank entities or touching a seed; entity descriptions up to `entity_description_chars` (`400`, was 160), cut at a sentence and with repeated sentences dropped, and with the sentences that share a word with the question first (`question_aware_descriptions`, on); the relation chains between the entities the question names (`seed_paths`); documents first and graph lines after; only entities and relationships sharing a significant word with the question (`question_gate`), seeds always kept; a name the question spells out seeds PageRank ahead of the vector matches (`keyword_seeds`); and the hybrid search's top ten chunks kept whole. Each change has its own setting, so the previous shape stays available.
- **A grounded answer policy in the chat system prompt** (`graphrag.answer_policy`, on). Graph lines count as evidence; the model says "not in the sources" only when neither the passages nor the graph lines name the answer, joins facts across them, answers every part of a multi-part question, and is told to read the passage where a moment happens sentence by sentence before declining a part. It is prompt-only — no retrieval or pin changes — and `false` restores the previous prompt.
- **The `graphrag` section of `settings.yaml` now reaches the app.** It was read only as engine defaults, so `graphrag` keys set there did not change the app's chat retrieval; with this release they do, which also applies any value you had set.
- **Ollama's default embedding model is `qwen3-embedding:4b`** (was `qwen3-embedding:0.6b`), and both setup wizards (CLI and web) give an Ollama-chat install `qwen3-embedding:4b` at its native 2560 dimensions (was `qwen3-embedding:8b` at 4096): on the Book One chat questions it retrieves the answer for 95 of 99, against 88 for 0.6b and 96 for 8b. An existing configuration keeps its model; changing the model needs a re-index.
- **`chaoscypher setup` sets `search.vector_dimensions` to the embedding model's native size on a first setup or when the model changes.** The 0.5.0 wizard never wrote it, so a model whose size was not the 1024 default failed every embed (a 768-dimension model) or was cut short (a 2560-dimension one). A re-run that keeps the embedding model keeps its dimensions — a new size drops the vector index and forces a full re-embed — and prints how to switch on purpose (`chaoscypher config set search.vector_dimensions`, then `chaoscypher source rebuild-search`). The model menu defaults to the registry's default model.
- **Deduplication groups by core type, and four settings are retired.** Same-name entities merge within one core type, so a `character` and an `author` subtype of Person merge, and the merged node keeps every subtype in `entity_subtypes`. `source_processing.dedup_type_compatibility_map`, `source_processing.entity_deduplication_similarity_threshold`, `extraction.domain_detection_sample_count` and `extraction.domain_detection_sample_chars` are removed; a `settings.yaml` that sets them still loads, with one warning per key.
- **A template named by name is the database's own before a built-in one.** On a database with its own `Person` template, `create_node` and `list_nodes` given `Person` use that template; two of the database's own templates with one name answer `AMBIGUOUS_TEMPLATE` and list them in `template_ids`.
- **A site's pages are never parked for confirmation, and Skip duplicates does not apply to them.** Each page extracts with the packs you chose or the packs detected for it.
- **A Markdown page imported by URL is named by its first heading** instead of "Untitled Page", in the web UI, the CLI and MCP alike (the stored file name follows one rule, so CLI and MCP file names change slightly).
- **A looser filtering mode now raises a domain's loop cap, and a stricter one can lower it.** A pack's `loop_max_entity_count` (the per-chunk entity count that aborts a looping stream) used to win over the slider, so a source on `unfiltered` (cap 200) still stopped at the technical pack's 30. At the default `balanced` the pack's cap applies as before; a mode you choose that is looser raises it to at least that mode's cap, a stricter one lowers it to at most that mode's cap (technical: 25, 30, 30, 75, 100, 200 from `maximum` to `unfiltered`). `minimum_alias_length` follows the same rule. A preset the pack names itself leaves its values as tuned. See [Domain packs and the slider](../reference/filtering-modes.md#domain-packs-and-the-slider).
- **A source carries a list of packs, and detection proposes up to two.** Every source extracts with the floor (`generic`: the eight core types and the core relationship labels) plus the packs it chooses. Detection now proposes every pack whose evidence clears the floor, at most two, by score; a near-tie proposes both, the higher first, instead of falling back to generic, and no pack over the floor is the floor alone, flagged low confidence. The stored proposal carries `packs` beside `detected_domain` (their first, or `generic`). Every surface that took a domain takes `packs`: `POST /sources`, `/sources/batch` (repeat the form field) and `/sources/url`, `POST /sources/{id}/extraction`, `/confirmation` and `/reclassify`, the MCP `add_document` and `confirm_extraction` tools, and the CLI's repeatable `--pack` on `source add`, `extract` and `confirm`; `domain` stays accepted as a one-element list (`generic` is the floor alone, `__auto__` detects), so a client that sends `domain` keeps working. `GET /sources/domains` names each domain's `role` (`floor` or `pack`). Sources gain `forced_packs` and `extraction_packs`, extraction jobs `forced_packs` and `detected_packs` (JSON lists, migration 0017, backfilled from the old columns); for one release `forced_domain` and `detected_domain` keep the first pack and `extraction_domain` records the packs' label (`historical+literary`), so the benchmark identity is unchanged for one pack. A GraphRAG profile rule's `domain` also matches a label that contains it.
- **Packs at import and in source settings, one template per core type, subtypes in the chat context.** The upload and confirm dialogs choose the packs with chips (`PackSelect`): the detection proposal arrives pre-selected, any pack can be added or removed, no chip is the floor alone, and at upload a switch leaves the choice to detection. The confirm dialog shows the proposed packs instead of the top three domains, and sends `packs`. A source's actions menu gains **Change packs…**, the same chips with a warning that the change re-extracts the source (`POST /sources/{id}/reclassify`). The source page shows the `+`-joined label with an icon per pack (new `extraction_pack_icons`), and *changed since extraction* reads every pack the source used. The commit creates one template per core type (at most eight) with the floor's icon and colour; `graph_nodes.entity_type` is the core type and the pack subtype stays in `properties.entity_subtype` (a merge's `entity_subtypes` too); an old per-type suggestion (`Character`) commits as its core type's. Entity chips and the canvas colour by core type and show the subtype in the label (`Person · Character`); `GET /sources/domains` lists each pack's subtypes with their own icons. The chat context's `({type})` reads the subtype when the node has one (`Pierre (character) child_of Count Bezúkhov (character).`), else the core type. Quality scores are the floor's per core type and core label, the packs' per subtype (`subtype_scores`) and extra label (`SCORING_VERSION` 9). For a source of two packs the finalize's type aliases, normalization rules, templates, quality config and fingerprint, and the content exclusions, now read the whole stack (they read nothing, or the first pack). **Settings → General → Chat context** has a switch for `graphrag.include_unevidenced_edges` ("Use unevidenced relationships in chat context", off). In the intelligence pack an informant, defector or recruited asset is now a Person (`human_source`), a collection source stays a Concept; in the political pack a parliament, bloc or party is an Organization and a political entity a state (Location).
- **The last three filters that deleted a record that says something keep it with a flag.** An entity whose cited sentence does not name it is kept when it carries a description, flagged `unevidenced` (the key relationships use) with the reason; an entity whose name is one of the domain's exclusion examples is kept when it carries evidence, flagged `excluded_name` with the rule; under strict edge-type constraints (every extraction plan) a relationship whose label no relationship type answers to is kept as `related_to`, flagged `unmatched_label` with the label as written, and one whose endpoints its type refuses is kept with its label, flagged `type_mismatch` with the reason. Only a record carrying nothing is still dropped. The flagged entities rank after the others in chat retrieval and hang off their document's "Unresolved (N)" node on the canvas; the flagged relationships rank last, with a capped one, and are drawn thin. Chat retrieval's `max_triples` selection now ranks every line by its full standing (a line touching a reference, an orphan or a doubted entity, and a flagged relationship, after the others) before the cap, the order the triple summary is cut by. New counters (migration 0016): `entities_unevidenced_kept`, `excluded_entities_kept`, `relationships_unmatched_label_kept`, `relationships_type_mismatch_kept`; `evidence_entities_dropped` now counts only entities with no description, and `relationships_dropped_type_unmatched` the two kept relationship kinds together.
- **No filter drops a record that says something; it is kept with a flag.** A name the plausibility score puts below the bar is kept when it carries a description or evidence, flagged `low_plausibility` with its score; an entity whose written type no core type answers to is kept as a `Concept` flagged `unplaced_type` (both counted, migration 0014: `plausibility_entities_flagged`, `unplaced_type_entities_flagged`); a relationship past a cap is kept flagged `capped`, walked at a tenth of an edge's weight and drawn thin (`relationships_dropped_capped` now counts them); a group, place or event written without a name (`the army`, `the village`) is kept as a reference like a person's; the alias cleaner keeps every alias the text writes (`Lise`, `Annette`, `Moskva`) and moves the others to descriptors; a one-word title folded into a name (`Emperor` into `Emperor Alexander`) is recorded as a merged name. The `data_tables` content category is no longer used by any shipped domain (it stripped table rows before extraction), and `code_blocks` no longer takes indented verse, letters or lines opening with "for", "if" or "while" for code.
- **An entity with no relationships is kept when it says something.** The commit used to delete every entity no relationship pointed at (unless orphan protection was on), description and all: 20 to 36 people, places and events on a novel-length source, among them characters whose only fact was in their description. Now an orphan that carries a description or an evidence sentence is committed with `properties.orphan: true`, and only one carrying neither is dropped. Chat retrieval reaches it by name or meaning and ranks it after connected entities; the graph canvas links flagged nodes (unconnected entities and unnamed references) to a grey **Unresolved (N)** node per source document, hanging off that document's source node, that starts closed and shows or hides them on a double-click, each node's hover and detail panel saying why it is unresolved, and the entity table shows the flags as chips; the identity resolver may later merge it into a connected node, which clears the flag. The `orphan_entities_filtered` counter now counts the orphans kept; the new `evidence_less_entities_dropped` counts the ones dropped (migration 0013).
- **A relationship the text does not state is kept, flagged, instead of deleted.** The extraction's evidence filter used to delete every relationship whose cited sentence it could not read as stating it, justification and all: on a novel-length source a third of what the model wrote (162 and 105 relationships on the two *War and Peace* Book One benchmark arms). Now such a relationship, between two entities of its passage, is committed with `properties.unevidenced: true` and the reason in `properties.evidence_reason`; only one with an endpoint that is no entity is dropped. Chat answers leave unevidenced relationships out by default (new setting `graphrag.include_unevidenced_edges`, off), the graph canvas draws them dashed and the edge panel shows the reason. When the identity resolver merges two nodes and two of their edges become one, the dropped edge's justification is kept in the kept edge's `properties.justifications`. The graph context's triple summary is now cut by rank (named before reference, evidenced before unevidenced) rather than by bytes. The new `relationships_unevidenced_kept` counter counts the kept relationships (migration 0015); `evidence_relationships_dropped` now counts only the invalid-endpoint drops.
- **Decoding is pinned by default: temperature 0 and seed 42 for chat and extraction.** The defaults were `ai_temperature` 0.3, `extraction_temperature` 0.1 and no seed, so the same document could extract to a different graph on re-import and the same grounded question could get a different answer and different citations each time. Now the same input gives the same output, which is what makes re-imports, retries and response caching safe, and what the benchmark measures (its rows refuse to pool across differing decoding). Raise `llm.ai_temperature` in `settings.yaml` or the Settings page for variety in chat answers; extraction has no reason to sample. Only Ollama honours the seed; hosted providers decode at the temperature alone. An existing `settings.yaml` that sets these keys keeps its values.
- **Regenerate gives a different answer.** Under pinned decoding a regenerated chat answer was the same answer. A regeneration now decodes at `chat.regenerate_temperature` (new, default 0.7) or `llm.ai_temperature`, whichever is higher, with a new seed for each regeneration (seed + n), and records both on the message. The first answer and ordinary turns stay pinned.
- **One placing of a stored node's type.** The commit and the CCX import store a node's type through the same function (`type_rescue.core_typed`): the core type, the subtype in `entity_subtype` when the node carries none, and a type no core type answers kept as a `Concept` flagged `unplaced_type` with `written_type` (the commit used to keep such a type as written). An exported source now carries its packs in stack order (`extractionPacks`, beside the sorted `extractionDomain` label), and an import restores them as `extraction_packs`.
- **Deleting a source keeps what another source also says (#795).** Identity resolution merges an entity that two sources both name into one node, but a node carried one `source_id`, so deleting either source deleted the merged node with the other source's relationships, or left the deleted source's names and description on it. The graph now records which sources attest each node and edge, with what each one wrote (new tables `graph_node_sources` and `graph_edge_sources`). Deleting a source, re-committing it and force re-extracting it all release the source the same way: what only it attests is deleted; a node or edge another source also attests stays and is rebuilt from what the remaining sources wrote (label, aliases, description), with nothing of the released source left on it, then re-embedded. A re-commit or re-extract writes the source back onto the nodes that survived under another source and folds its reading in again, so a later delete of that other source keeps it. A template the released source owned is deleted when unused and otherwise handed to a source that still uses it. The orphan cleanup no longer deletes a node another source attests, nor a template still in use. See [Knowledge Graph Storage](../architecture/graph-storage.md#provenance-membership-and-the-enabled-filter).
- **Disabled sources hide by membership.** A merged node stays visible while any of its sources is enabled, and the per-source counts count it once under each source; the graph listings, counts, search, chat retrieval and template listings read the same rule. The `Edge` payload gains `source_id` (its home source, as on `Node`), and `GET /api/v1/edges?source_ids=` returns the edges any listed source attests, not only those homed there.

##### Security

- **The PyPI packages carry PEP 740 attestations.** From this release every wheel and sdist of the four `chaoscypher-*` packages is published with a Sigstore-signed provenance statement tying it to the public repository's publish workflow, which PyPI shows on each file and attestation tooling can verify; the publish action is pinned at `pypa/gh-action-pypi-publish` v1.14.3, which drops a revoked certificate authority from the store it trusts (GHSA-5xjx-3w67-w9x9).
- **Imported packages have their key signatures checked.** An import is refused when the package declares an ed25519 signature that does not verify against its manifest bytes, which catches a package changed after signing. A signature kind this install cannot verify (sigstore) is skipped with a warning, an unsigned package imports as before, and the check does not say who signed the package.
- **A memory's words, and the values a tool was given, never reach the log.** Every database engine is built with `hide_parameters`, so a database error keeps its kind and statement but never the values (there is no opt-out). A failed tool logs its name, the error's type and the code — never the message or traceback — and the tool-executing log line records parameter names only. While a memory is stored, linked, relinked or forgotten, log records keep only an allow-list of safe fields, with tracebacks at DEBUG only.
- **Chat runs only the tools it offered the model.** The chat loop ran any tool name the model returned against the full tool registry, so a model — or instructions injected through a retrieved document — could call a tool chat never offered, such as `delete_template`, with no approval prompt under the default `chat.tool_approval: never-ask`. A name outside the turn's tools now gets an "Unknown tool" error.
- **The address guard judges an address by its value, not how it is written.** Cloud metadata addresses were caught only in dotted form: the integer form of `100.100.100.200` and IPv4-mapped forms such as `[::ffff:100.100.100.200]` passed both policies, so a URL import, site crawl, workflow HTTP request step or settings URL could reach a cloud metadata service. IPv4-mapped addresses are now unwrapped before every check, and the Alibaba (`100.100.100.200`) and Oracle (`192.0.0.192`) metadata addresses are blocked as networks.
- **A small crafted upload can no longer use up the server's memory.** An OpenAPI spec with a self-referencing object expanded 1,582 bytes into 805 million characters; each spec now gets `loader.openapi_max_schema_chars` (default 10,000,000) of expanded schema. An XLSX workbook that points every cell at one long shared string is rejected past `loader.xlsx_max_content_chars` (default 50,000,000), and a PDF page declaring a huge size is rendered for vision at most `llm.vision_max_render_pixels` (default 25,000,000).
- **A domain pack's detection regex can no longer hang detection.** Detection patterns now run in the same sandbox as content-exclusion patterns: 512 characters at most and 100 ms per match; a pattern that is too long or invalid is logged and skipped.
- **A queued indexing task can no longer delete directories outside its own images folder.** A task whose `file_id` or database name was an absolute path or contained `..` would, if its loader failed, delete the directory it named. Both must now be a single plain path segment.
- **Deleting a source added through MCP `add_document` no longer wipes the MCP sandbox.** Index-only `add_document` stores the file where it already sits in the sandbox, and deleting the source removed its parent directory — the sandbox root. File cleanup now deletes only a per-source directory inside the database's own staging root.
- **`chaoscypher compose` refuses local-path dependencies declared by Lexicon Hub packages.** A downloaded hub manifest could name a `/`, `./` or `../` dependency, and the resolver read it from your disk into the composed database; hub packages may now depend only on hub packages.
- **The container entrypoint no longer writes through a planted symlink.** It runs as root but wrote the edge auth token and `dhparam.pem` at fixed paths in folders the app user can write; both now go to a new temporary file renamed into place, and a symlink at `dhparam.pem` stops the boot.
- **Tighter path check on the source-image route** (defence in depth): the file must sit exactly one source directory below the database's fixed `images` root.

##### Data correctness

- **Every database gets the built-in templates it is missing, each time it is opened.** A database built through the CLI, `chaoscypher mcp`, the Python API or a package import got the migrations but not the shipped templates, so `create_edge` with the default `system_template_link` failed its foreign key. Every open, in read or write mode, now adds the missing templates, which repairs an affected database the first time it opens.
- **Foreign keys are enforced again after an upgrade.** The migration connection went back to the pool with foreign keys off, so the first session after an upgrade could insert an edge naming a template that does not exist.
- **A node or edge a person made is never deleted or rewritten when a source is removed.** Rows made with `create_node` and `create_edge` (MCP, the API, the Python API, the CLI and the chat research tool) are marked `person_made` (migration `0025`); removing a source that attests one removes only that source's link to it, and a merge attaches rather than folding into it.
- **Hybrid search gains a real keyword half.** Chunks were never in the full-text index and every word of a query was required, so a question matched no chunk and almost no node. Chunks now have a full-text index (an existing database fills it on open), a query matches any significant word or a quoted phrase, chunk search returns only chunks, relation-type templates are no longer GraphRAG seeds, and provenance chunks keep PageRank order. A dropped or emptied full-text index is rebuilt on open.
- **Vectors are unit length, and a cut vector is cut on purpose.** Every embedding provider returns unit-length vectors; a model whose native size is larger than `search.vector_dimensions` is truncated and re-normalised (logged as `embedding_mrl_truncation`), and one whose vectors are shorter is refused — the Ollama provider used to cut `qwen3-embedding:4b`'s 2560 dimensions to 1024 silently and store them un-normalised. Vector tables use the cosine metric; an older table is rebuilt on open with its vectors normalised. A rebuilt node is embedded from the same text extraction embedded (it used to drop the aliases).
- **Extraction's merges follow one name rule and keep the better-supported name.** A short name that fits two fuller names is not merged; support ranks above accents when choosing the surviving name; an alias counts as evidence only where its own chunk writes it; and a bare title or descriptor ("the count") is a reference, folded only on its own names and otherwise kept flagged `descriptor_reference`.
- **A failed backup can no longer replace a good one.** A `VACUUM INTO` that errored or was killed left an empty database under the backup's final name, which listed as the newest backup, pushed a good one out of retention and, restored, wiped the live database. Backups are now written under a `.partial` name and renamed only on success.
- **Citations survive a second package hop.** Importing a re-export of an imported package (A to B to C) skipped every entity citation as unresolved; every reference to a node now uses the id the node record carries.
- **Exports keep what they used to drop.** A disabled source's node templates are exported with its nodes, and parallel edges without properties are written out in full instead of collapsing into one on import.
- **A `.ccx` uploaded through the app indexes its knowledge-only nodes for search**, and an imported source whose vector push failed is marked `degraded` with retries queued instead of reading `indexed` while missing from semantic search.
- **A search-index rebuild keeps the "needs full reindex" flag when re-embedding fails**, so vectors from an old model are no longer left in place behind a cleared flag.
- **MCP extraction keeps to its source's state.** `submit_chunk_extraction` refuses submissions for a source that is not under MCP extraction (`INVALID_STATUS`), so stale rows can no longer be committed as current, and MCP extraction now respects a source's `content_filtering: false`.
- **Extraction keeps lines and records it used to lose.** A line with an empty last field (`E|Napoleon|Person||1.0|S1|`) is no longer dropped as malformed, a named record with a description survives the junk filter, edges connect by entity index before entity name, and the packs chosen in **Confirm extraction** win over the upload-time choice. A runaway relationship pass is now cut by the loop detector too.
- **`create_node` and `update_node` over MCP index what they write** (keyword, and vector when an embedder is set up), `create_node` accepts a template's name, and `create_template` advertises the property schema the server actually accepts.
- **Pricing and stats add up.** Cloud prices come from the model registry the Settings page shows, so `claude-opus-4-6` and `4-7` bill at $5/$25 (not the opus-4 $15/$75), every `gpt-5.x` and `gemini-3.1` model at its price (not $0) and `gemini-2.5-flash` at $0.30/$2.50; versioned OpenAI model names the registry does not list are priced by the longest matching prefix (`gpt-4.1-mini-…` was billed as `gpt-4.1`); `DELETE /llm/stats` resets the token and cost totals and prunes the LLM queue only, leaving the operations history alone; and a chat turn that ends in an error counts against the daily spend cap.
- **Smaller fixes.** `normalizer.gibberish_threshold` takes effect (the cleaner used a fixed 0.5); the Python API's `embed(model=…)` and `embed_batch(model=…)` work; `Engine.process_document` keeps its citations; and `extractedBy` given as an object imports as `name@version`.
- **Source deletes that merge, and CCX imports of merged entities, keep each source's own reading (#795 follow-ups).** After a delete, the identity resolution's search step rebuilt the whole node keyword index under the database's write lock whenever it merged anything (11 s at 200,000 nodes); it now rewrites only the rows of the nodes it changed (0.2 s). A resolution that failed partway left the nodes it had already merged away in search and their kept nodes un-embedded; the cleanup now covers every merge that committed. A user template released with its source could be folded into a system template of the same name and lose its own description and properties; system templates are no longer candidates. A CCX import that cited an entity already merged with other sources recorded the merged row, with every source's names, as the importing source's reading, and overwrote the home source's reading with the package's; a later delete then brought a deleted source's names back. The import now records what the package says for each entity, leaves the other sources' readings alone and rebuilds the node from all of them, so re-importing a package into an entity other sources share can change that node's label and home source (the survivor ranking chooses among every source's reading); the rebuilt node's vector is cleared, so the import's indexing re-embeds it from its new text. A package that cites an entity another package already imported no longer overwrites that package's reading: deleting the second source brings the first one's text back. A rebuild after a release no longer folds identical readings into each other (two sources of one bundle citing one entity): such a node used to gain `resolved_from` and `merged_names` of its own label and move its home to whichever source id sorted first.
- **Retrieval, extraction retries and decoding now do what they say.** A source you disable no longer reaches chat retrieval: in a 120-question measurement a disabled source reached all 120 contexts and now reaches none, and a narrow scoped search over a large index runs in about a seventh of the time (2.47 s to 0.34 s for a 5-chunk scope over 179k vectors). Regenerate gives a different answer (see Behavior changes). Unparseable extraction output or a loop abort now climbs the retry ladder while an attempt is left, a rerun starts from the first rung rather than the one the last attempt stopped on, and a chunk rescued by a retry is counted on the source page. The Ollama provider reads its seed, temperature and repeat penalty once at the start of each call, so a streamed answer is decoded with exactly the values its record shows; the load balancer hands each settings configuration its own provider instead of sharing one; and a quota-exceeded 429 from a hosted provider fails at once instead of retrying.

##### Reliability

- **`create_edge` checks what it names, and one failed call no longer breaks the server.** It answers `UNKNOWN_TEMPLATE` or `UNKNOWN_NODE` instead of a foreign-key failure, and a failed write no longer leaves a long-running `chaoscypher mcp` session needing a rollback nobody issued, which failed every later call. A busy database is recognised by SQLite's result code rather than a phrase, and a cancelled write rolls its transaction back instead of holding the writer lock.
- **A new database is built, not upgraded.** Building a database's schema the first time takes no backup and leaves no upgrade record, so the web app shows no post-upgrade notice, the **Maintenance** page offers no rollback and MCP `upgrade_status` reports nothing. Two ways a first install looked like an upgrade are gone: `chaoscypher upgrade`, `chaoscypher db migrate apply`, the Maintenance page's **Apply** and MCP `apply_upgrade` on a database not built yet backed up the empty file and recorded every revision as a data-changing upgrade; and a first build cut short (a crash, a restart, a hot reload) left the baseline's tables without a version, which the next start took for a pre-Alembic install and upgraded behind a backup (or blocked on, when the baseline was itself cut short). Such a database holds no rows, so the next start now drops what was built and builds it again. A database with rows and no version is still upgraded behind a backup, and a database at an older revision still gets its backup, notice and rollback. A data-changing upgrade's record (the notice and the rollback) now lasts until the next upgrade or a rollback, where any later open used to clear it; an explicit apply after it takes a backup of its own instead of reusing that one; and a process that waited for another's first start builds the database itself when that start did not finish, instead of serving it half-built.
- **The app's own logs stay on after a database upgrade.** An upgrade or fresh install run inside the app replaced its logging setup and switched its loggers off until a restart; migrations now set up logging only when Alembic runs as its own command. Committing a source through the engine also reuses the engine's embedding model instead of loading a second copy.
- **Tool calls in streamed chats work on OpenAI, Anthropic and Gemini.** The streaming adapters kept only the last chunk that carried a tool call, so a call whose arguments arrived in fragments came out with no name and no arguments. Streamed OpenAI chats now report token usage, Gemini's streaming usage and finish reason are accurate, and Anthropic and Gemini replies whose content arrives as a list no longer fail mid-stream.
- **LLM errors are classified by their status, not by digits in their text.** A context-length rejection whose token count happened to contain `429` or `404` ("142901 tokens") was retried as a rate limit or failed as a missing model; it is now a context-length error. A 401 or 403 is an authentication error and is never retried, even when its text lacks the usual words ("Country, region, or territory not supported"), and a request id containing `504` is no timeout. A non-streamed Ollama answer that omits a token count no longer crashes, an Ollama tools stream on a model that cannot call tools says so as the non-streamed path does, a failure inside the thinking fallback is a classified error, and turning `llm_enable_priority` off now reaches every Ollama instance.
- **Ollama failures are retried, and an untagged model name works.** Connection failures, timeouts and a connection dropped mid-answer now raise the retryable error, so a chunk is retried instead of failing for good when Ollama restarts; a streamed Ollama call keeps its token counts and timings; and a model configured as `llama3` matches Ollama's `llama3:latest` in the health check and the embedding probe, which used to block chat and import.
- **A looping chat answer is stopped.** The first model call of each chat turn stops when one line repeats `chat.loop_max_consecutive_lines` (8) times in a row or any line appears `chat.loop_max_line_occurrences` (25) times; a loop while thinking is asked again once with thinking off, and a loop in the answer keeps the text before it.
- **Stop works while a chat turn is still queued.** A Stop clicked before the turn reached the LLM was thrown away and the turn ran to the end; the flag is now cleared when the turn ends and checked before the first provider call. A tool-approval decision made right at the deadline is honoured.
- **A source waiting for the extraction slot no longer stays stuck at `indexed`.** A fatal chunk failure, an import whose analysis produced no chunk groups, and the recovery pass marking a source failed all freed the slot without starting the next waiting source; a user cancel or abort of an extraction now starts the next waiting source too.
- **`chaoscypher compose build --no-clean` never loses the composition it started from.** A failed upsert build restores the composition it built onto. The pre-build copy is taken before the build starts and renamed into place only when whole, so a copy that fails on a full disk stops the build with the composition untouched; Ctrl+C or a cancelled task restores before exiting; and a copy found at the start of the next build is treated as the last good composition and restored, never dropped.
- **Rerunning a chunk on a finished extraction completes**, instead of leaving the source at `extracting` until a restart; and a retried chunk points at its new queue task.
- **MCP extraction recovers from failures.** A `finalize_extraction` that failed before the graph commit returns the source to `mcp_extracting` with its submissions kept, so it can be retried; `get_extraction_tasks` returns a source with no chunks to `indexed` instead of locking it; a failed index-only `add_document` marks the source failed; and `wait_for_document` no longer reports `completed` for a file that never finished.
- **Workflow runs end the way they should.** Cancelling a running workflow stops it and it stays cancelled (cancel set a flag nothing read); a run whose worker crashed is marked `FAILED` instead of replayed from step one; and a run that fails validation is marked failed instead of blocking every later run as busy.
- **Pausing also stops search indexing of imported sources** (the source is marked search degraded, and `POST /api/v1/search/indexes` clears it).
- **A `settings.yaml` that still sets `benchmark.vram_presets` no longer stops ChaosCypher from starting.** It is a retired key, ignored with a warning — the fix for v0.5.0 installs that fail to start with it. Environment variables now also reach nested settings in every section (`CHAOSCYPHER_MCP__MEMORY__WAIT_SECONDS` was refused as unknown input).
- **Uploads over 1 MB no longer fail with 413** on Lexicon publish (every deployment) and on multi-container `.ccx` import; both now carry the upload size limit and the uploads rate limit.
- **The multi-container Cortex gets time to finish in-flight requests when it stops** (`stop_grace_period` from `CHAOSCYPHER_STOP_GRACE_PERIOD`, default `60s`), and `SUPERVISOR_LOGLEVEL` reaches the all-in-one container.
- **Diagnostics never freeze or balloon.** A diagnostics bundle takes only the last 8 MB of each log instead of reading whole files into memory, and reading process status no longer blocks Cortex when supervisord is stuck. The extraction-ready check probes Ollama instances in parallel instead of adding a 5-second timeout per unreachable instance to every chat send and upload.
- **Startup and shutdown.** `chaoscypher serve --database` names the database with `CHAOSCYPHER_CURRENT_DATABASE` (the old variable emptied the `database:` settings section in the server); `chaoscypher mcp --database NAME` on a new database migrates cleanly; `chaoscypher mcp` needs no LLM to start; the Docker stack's recovery leaves memories to the link step; CLI sessions no longer fail on teardown under Python 3.14; and a CCX import keeps the Lens, Workflow and Workflow Step templates under any id.

##### Performance

- **GraphRAG chat retrieval batches its graph and chunk reads.** One windowed edge query per batch of seed ids instead of two queries per node, and one narrow filename read per database; on the benchmark's 741-retrieval sample a run drops from 6.9 s to 3.1 s with every retrieval byte-identical.
- **MCP extraction no longer gets quadratically slower on long documents** — 400 chunks went from 24.5 s to 0.3 s of task bookkeeping.
- **`traverse_path` reads only the edges it expands**, not the whole edge table on every call; the graph canvas reads pipeline flags only for the rows it draws (about 4 s per load at 50,000 nodes); and GraphRAG builds only the provenance chunks that survive the cut.
- **Lighter work on the worker.** `summarize`'s clustering no longer builds a chunks × clusters × dimensions array (about 473 MB on a novel-sized source); committing entities looks up templates once per commit; import commits reuse the worker's embedding provider; normalising and OCR cleanup run off the shared event loop; name folding during extraction is cached; and search results, whole-graph loads and `.ccx` imports each do less repeated reading.

##### CLI

- **`chaoscypher memory relink` links pending memories now**, oldest first and ignoring the backoff: `--limit`/`-n`, `--dry-run` (counts per state), `--include-empty` and `--database`/`-d`. It prints one line of counts and never a memory's text, and exits `0` when nothing is left unlinked, `3` when something still is, `1` on error. To link from your own timer instead of at server start, set `mcp.memory.relink_on_start: false`.
- **`chaoscypher source rebuild-search --embed-missing`** embeds only the chunks and nodes with no vector yet; it is refused while vector search is off and after an embedding model change.
- **`chaoscypher mcp` stops cleanly.** SIGTERM and Ctrl-C give back the memory being linked and exit `143` / `130`, and a stopped stdio server no longer aborts with a core dump. `--profile`/`-p` picks the tool profile, and `-d default` serves the database named `default`.
- **Retry and resume work.** A source in `error` can be retried in place (the retry checks accepted a `failed` status nothing writes), and Ctrl+C during `source add` or `source extract` returns the source to `indexed` with its chunks and embeddings intact, so the same command resumes it.
- **`chaoscypher setup --non-interactive` keeps the environment's Ollama URL** instead of writing `localhost` over `CHAOSCYPHER_OLLAMA_URL`, and says so when `--vram` matches no preset.
- **Smaller fixes.** `source get` shows all its fields; `graph node create --interactive` reaches its wizard; `diagnostics` includes your settings with secrets masked; `doctor` probes the ports Cortex actually uses (`cli.api_port`, `ports.web_ui_api`); `db delete` no longer deletes the default or current database through a name that differs only in case; `lexicon pull --extract` points at the `.ccx` to load; the "no LLM provider" hint names `llm.chat_provider`; four `--help` screens no longer print a literal `\b`; and the `--quick`, `graph node delete` and `mcp` help texts say what the commands do.

##### Interface

- **Unresolved nodes hang off their document in a small "Unresolved (N)" node.** The graph used to draw flagged nodes in a dashed box with orange tags off to one side. Each document now gets its own grey Unresolved node beside its root, half a root's size, collapsed at first: double-click it to show or hide its nodes, and pressing Enter in the canvas search opens it when the match is inside. Hover a node to see why it is unresolved.
- **The import page explains packs and hides an empty picker.** With "Detect packs automatically" on, the pack picker is hidden; an info icon beside the switch says what packs are, with examples from the packs installed.
- **The dashboard background draws at once.** It waited for the page's statistics to load; now only the statistics wait.
- **A tool-approval prompt opens over the chat that asked for it** — a background chat's prompt used to open over the chat on screen, was sent with the wrong chat id and timed out as a denial.
- **The Confirm extraction dialog offers only what the confirm endpoint accepts and sends only what you changed** (every Confirm used to send `content_filtering: true`), and the source page falls back to the overview when its open tab disappears.
- **Times read right.** Backup times are shown in your local time (the UTC stamp was read as local), and future dates read "in 2d" instead of "just now".
- **Smaller fixes.** A failed Retry or Re-extract no longer shows a "queued" toast; a bulk delete that fails partway still tries every row and names the failures; Settings → LLM accepts 0 for Max Retries; Save and Reset refresh every settings view, Reset re-checks the LLM health banner, a late Ollama check or cloud-key verdict no longer overwrites a value you have edited since, and a cleared dimensions field keeps its value; and three selects gain accessible names.

##### Benchmark

- **The chat board is scored by a stricter, fairer scorer, so chat rows from v0.5.0 are not comparable.** The chat-probe scorer goes from version 2 to 9: common decline wordings count as declines, capitalised sentence openers are not invented names, a failed fact inside a negated clause is not stated, a list answer naming a member the gold answer leaves out fails, and a phrase quoted from the context no longer fails. Probe citation checks fold accents. Rescore older runs.

It is a `needs_confirmation` migration: it applies at startup behind a verified backup, whatever `migrations.auto_apply_destructive` says, and is recorded as a data-changing upgrade that can be rolled back; when there is no room for the backup the database waits in maintenance mode until it is applied from the maintenance page or with `chaoscypher db migrate apply`. Each membership keeps a copy of the row's properties, so stored graph properties roughly double in size. - **Destructive operations:** `0019` rebuilds `graph_nodes`, `graph_edges` and `graph_templates`; no column is dropped. On first open, vector tables from before this release are also rebuilt to the cosine metric with their vectors normalised, and the new chunk full-text index is filled, so a large database opens slower once.
- **Auto-backup:** by default all six data-changing migrations apply at startup behind one verified backup per database, written beside it as `<data_dir>/databases/<database_name>/backups/pre-<revision>-<timestamp>.db` — expect a file the size of that database's `app.db`, and leave room for `0019` to roughly double the stored graph properties. When the backup cannot be taken (disk), the database waits on the **Maintenance** page until it is applied there or with `chaoscypher db migrate apply`. ### September 2026

#### v0.5.0 (2026-09-26)

The first feature release since v0.4.0 — 30 commits since v0.4.3, 19 of them changing product code. Two themes. Knowledge in motion: a package you build can now be mounted straight into an MCP host as a one-line config entry, or stacked with other packages into a single database your agent queries. And measurement: two benchmark boards — extraction instruction probes and grounded chat, both scored pass/fail without a judge — a `/leaderboard` page that blends them into one Overall score, model pickers in the app that read the same numbers, and a bridge that benchmarks the model behind any MCP client on the same suites. One additive migration (`0007`) and no breaking changes to the product API; the MCP benchmark tools, new here, changed payload shape while they were landing — see **Upgrade advisory**.

##### Features

- **`chaoscypher mount` — pull a package and serve it over MCP.** One idempotent command resolves a `.ccx` (a local file or a Lexicon Hub `owner/name`), imports it into a database of its own — templates, knowledge, workflows **and** sources, chunks and citations — indexes it for search, and hands that database to the stdio MCP server. A `mount.json` SHA-256 marker makes every later launch skip the import, so the command belongs directly in an MCP host's config rather than in a setup script. It is first-run-safe: no chat or extraction LLM is needed, because the host's model asks the questions. All output goes to stderr, since stdout is the JSON-RPC channel. New reference page: `reference/cli/mount.md`.
- **`chaoscypher compose` works on CCX 3.0.** It was a pre-3.0 prototype: the merger read a `data/*.json` layout that no package has (so every build produced 0 entities), `up` launched a Cortex entrypoint that exited 0 at import time, and `down` could not stop a detached server. The merger now imports each resolved package into a real runtime database through `CcxImporter` — templates, knowledge, sources, chunks, citations and IRIs intact — counts totals from that database, records its inputs in `composition.json`, and runs a best-effort embedding/vector indexing pass afterwards. `up` launches Cortex the way `serve` does, logs to `<output>/server.log`, watches the child through a startup grace period and fails with the log tail if it dies; `--detach` records `compose.pid` and refuses to stack a second live server; `down` does SIGTERM→SIGKILL with the configured grace, cleans stale records, and says "nothing running" instead of claiming success. `build` writes a one-time runtime `settings.yaml`, so a composed server is healthy in about 6 seconds instead of a minute of Valkey retries.
- **`compose init` and `compose mcp`.** `compose init [--name] [PACKAGES…]` writes a starter `axiomatize.yaml` (a commented example when given no packages; refuses to overwrite without `--force`). `compose mcp [-c] [--mode] [--build]` builds the composition if its database is missing and then replaces the process with `chaoscypher mcp` on the composed database — stdio passes straight through and the host sees one pid, replacing the older `compose run chaoscypher mcp` incantation in the docs and in the Claude Desktop/Code snippets.
- **Chunks of transcribed audio and video carry `start_time` / `end_time`.** The audio and video loaders joined Whisper's transcript and threw the segment times away, so a citation into a recording could say which file but never when. Chunks now carry the seconds of the recording they came from, the way PDF chunks carry a page number, and the position travels everywhere a chunk goes: GraphRAG provenance and vector chunks, `search_chunks`, `summarize`, the search-engine dicts, and chat citation resolution. `ChunkResponse`, `ChunkReference` and `ChunkResult` expose both fields.
- **An instruction-probe benchmark tier, and a seed that works.** `chaoscypher benchmark` gains 65 probes across five sections: one probe per extraction instruction, each with a passage constructed so the correct extraction is unambiguous and checks a reader can verify by eye, scored pass/fail and headlined as a tier-weighted pass rate. Probes call the real extractor with the real prompts, settings pins and line parser, so a pass means the product could use the output. A "carrier" tier splices each probe into a real ~3,000-character extraction group from the corpus, testing production density rather than production length. Six 32 GB-class local extractors were added, and the local-model bar raised from 24 GB to 32 GB.
- **A grounded-chat board — the graph answers questions, scored pass/fail with no judge.** `chaoscypher benchmark` gains a second board: every labelled question is scored by pure functions — the answer names the terms a correct concise answer must contain, carries no names or numbers the retrieved context does not support, leads with the right entity when two are confusable, declines when the sources cannot answer, repeats none of the wrong facts the question declares, and passes a completion gate. A judge model is now optional rather than required. The fixture is *War and Peace* Book One (113,934 characters against a ~7.7k retrieval window, so a question is answered from retrieval and not from the whole corpus) with 80 labelled questions: single-hop, paraphrase, multi-hop across chapters, fine-grained confusable pairs, and out-of-scope questions with decoys from the rest of the novel. An `answer_terms` item may be an any-of alias group (`Mary` / `Andrew's sister`), matched as a whole phrase, so "the princess" no longer satisfies "little princess". Each board reports its retrieval floor — the questions every scored model failed. Getting there fixed the retrieval path underneath: the chat stage indexes its own snapshot with the stage embedder, the reference graph is a committed graph snapshotted through SQLite's backup API and read under the database name its rows carry, and GraphRAG search in the benchmark is wired with the indexing repository and source storage, so the model sees chunk text and not just entity names.
- **`/leaderboard` — six columns, one Overall score, and the app shows the same numbers.** A top-level page ranking local models on Model, Overall, Extraction, Chat, VRAM and Speed. Each score is one percentage with the counts, the pass rule, the retrieval floor, cut-off answers and the run time in a panel that opens on hover or keyboard focus (a bottom sheet under 760 px). Every measured column header sorts on click, best first, with unmeasured cells always last. Overall is 0.6 × extraction + 0.4 × chat, extraction is in-chunks × ⅔ + isolated × ⅓, and a run that did not finish counts as zero. The weights are written into the exported data rather than recomputed per page, so the leaderboard, the homepage teaser and the app's model pickers agree — VRAM is a gauge against the budget you pick, speed is a word on fixed anchors with the seconds in the hover, and the table holds its layout with no horizontal overflow from 375 to 1280 px.
- **Benchmark any MCP client's model on the same suites.** Five read-mode tools — `start_benchmark`, `get_benchmark_task`, `submit_benchmark_output`, `get_benchmark_progress`, `finish_benchmark` — let the model behind an MCP client (Claude Code, Claude Desktop, Cursor, …) run a suite against itself, one pass per tool call, with every prompt rendered by the extractor itself and scored by the same checks a local run uses. Two suites ship: the extraction probes, and grounded chat answered from a reference pack's graph through the same retrieval and embedder the local chat stage uses. Reference packs are written and listed with `chaoscypher benchmark reference export` / `reference list`. Integrity is part of the bridge, not the client's good manners: no verdicts before `finish_benchmark`, each stage answered exactly once, finished runs closed, and run state kept in a JSON file re-read on every call so an interrupted run resumes. A finished run writes an ordinary results file marked `pins_applied=false` and `harness="mcp:<client>"`, and the leaderboard carries harness rows on the main board, marked in the model cell — the probes, parser, checks and reference graph are the same, but temperature, seed and thinking cannot be pinned through a client. `scripts/benchmark/run_mcp_suite.py --client claude-code|codex` drives a run task-by-task in a fresh isolated session with only the two task tools allowed, so the model never sees the suite's arguments or its own results.

##### Data correctness

- **Extraction truncation was invisible four layers deep, and a truncated extraction scores *higher* than a complete one.** Measured twice, independent of thinking mode: `gemma4:31b` scored 72.09 truncated vs 67.02 complete, and `qwen3.8:27b` under a forced 300-token budget scored 76.49 vs 71.25 — so any model hitting the token ceiling posts an inflated result. Core computed the signal correctly all along; it died on the way to anyone who could act on it. The CLI ingest path received the metrics dict from `extract_single_chunk` and discarded it, so every CLI ingest (`chaoscypher source add`) dropped truncation on the floor and `chaoscypher source get` reported a clean ingest for a source whose chunks were cut off; `get_file`'s narrow projection omitted the counter columns, returning `None` indistinguishably from zero; and nothing in the product had ever read these counters, which is why a blind projection went unnoticed. A new `get_source_counters` validates against the same allowlist the increment uses, so the read and write sets cannot drift, and the leaderboard now warns by name about any model whose extraction did not run to completion.
- **Exported packages carried zero node templates** — `_templates()` dropped every `is_system` template, and extraction files entities under system templates, so every mounted, loaded or composed entity arrived untyped.
- **A CLI-built package silently lost every citation** on the far side of a load or mount: `package export` hard-coded `include_sources=False` on the false premise that the CLI "has no sources repo", when the storage adapter implements `SourceStorageProtocol` exactly as the worker export path uses it.
- **`python -m chaoscypher_cortex.main start` built the app and exited 0** — `main.py` had no `if __name__ == "__main__"` guard, and that is the exact command both `chaoscypher serve` and `compose up` run. Pinned by a subprocess test.
- **Benchmark runs advertised determinism they never applied.** `_build_temp_context` pinned temperature and seed behind `hasattr` guards keyed on field names `LLMSettings` does not have, so both assignments silently no-opped while the result row recorded `seed=42, temperature=0.0`. Five identical runs spanned 3.5 score points before the fix and are byte-identical after it. Two product defects surfaced alongside: there was no seed plumbing anywhere (`LLMSettings.seed` is new, threaded through the provider factory and applied by the Ollama provider — default stays `None`, so nothing changes unless you pin it), and `thinking_for_extraction` was read by the schema extractor but never passed by `ai_entities.py`, the path every CLI ingest (`chaoscypher source add`) takes, so setting it true did nothing. Its default is unchanged.
- **A thinking verdict could cross models** — `run_benchmark` reuses one dataset object across every model while the capability probe only runs for Ollama providers, so a hosted model inherited the previous Ollama model's `thinking_honoured`.
- **The `\|` escape the extraction prompt documents never worked.** The parser split on every `|` and unescaped afterwards, so the escape only ever took effect in the last field: an entity named `Rostov \| Bolkonsky & Sons` produced one field too many and the whole line was dropped. `split_fields` now honours backslash escapes, the entity and relationship prompts and the UI rules block state the `\|` and `\\` rule, and probe A2-hard is re-enabled now that it scores an instruction the model was actually given.
- **Entity lines survived neither a missing nor a doubled `aliases` field** — 740 + 18 such lines across the saved probe runs. Local models omit the slot (`E|Rousseau|Author|1.0|S7|…`) or add an empty field after it, and the positional parse dropped the whole entity. `parse_entity_line` now locates fields by anchoring on the confidence + sentence-reference pair instead of counting from the left; a non-blank field between the aliases and the confidence, or a spaced `" | "` inside a name, is still rejected as an unescaped pipe leak, so realignment can never store a corrupt entity.

##### Upgrade advisory

All five plugin-loading services now interpolate the host value.

##### Data correctness

- **Crash recovery spent two units of the retry budget per cycle** — `requeue_atomic.lua` bumped `attempts` on top of the worker's own claim-time increment, so a `max_tries=5` task with `retry_on_crash=True` got **3 dispatches, not 5**, then went terminal reporting "crashed after 5 attempts". The blast radius is the four crash-retryable operations with no owning resource — `execute_workflow`, `execute_step`, `export_graph`, `export_by_sources` — for which the queue budget is the only recovery layer. The reconciler now also resolves `max_tries` from `workers.yaml` rather than the built-in default.
- **A re-delivered chunk task could double-count and finish the job early** — `OP_EXTRACT_CHUNK` is crash-retryable on the claim that a DB short-circuit makes re-running safe, but the short-circuit only caught a `completed` row; a row in `running` passed straight through and neither write path re-checked. Two deliveries of one chunk produced two terminal writes and two job-counter bumps, satisfying the finalize predicate one chunk early and leaving `completed_chunks` permanently wrong for the progress UI. Both transitions are now guarded updates returning a rowcount, and the handler bails before the billable LLM call when it loses the claim.
- **A graceful worker restart lost crash-retryable work** — the shutdown drain's `CancelledError` arm wrote terminal `status="cancelled"`, which is exactly the status the requeue script and `retry_task` refuse to resurrect. That inverted the recovery contract: a hard `SIGKILL` recovered the work and a clean restart destroyed it.
- **A queue heartbeat that lapsed could never be refreshed** — `refresh_heartbeat` issued an `EXPIRE`, which is a silent no-op on a key that has already expired, so a 31-second stall condemned a multi-hour task as abandoned and the reconciler requeued it for duplicate execution. It is now a `SET`-with-`EX`.
- **Clearing completed-task history raised `WRONGTYPE` whenever any task was running** — `clear_old_completed_tasks` ran `HGETALL` across a glob that also matched the heartbeat strings; it now skips them.
- **The commit-time orphan filter ignored the source row** — the queued commit task's `file_info` is a narrow projection carrying neither `filtering_mode` nor `protect_orphans`, so the filter always resolved the engine default and dropped orphans for minimal/unfiltered sources and for rows with `protect_orphans=True`. It now mirrors the finalizer's cascade (payload > row > engine default).
- **"Reset to Indexed" on a stale MCP source broke the whole sources list** — the UI sent `processing_status: "ready"`, which no response model accepts, so that source and every subsequent `GET /sources` returned 500. The hook now sends `indexed`, and a PATCH with a phantom value is a 422.
- **A rejected `workers.yaml` value collapsed the Operations queue from 8 concurrent to 1** — a bad value fell through to a boolean rather than to the worker type's base default.
- **Compound archive extensions were silently skipped** — `GenericHandler` now defers member support to the registry, so an inner `.tar.gz` recurses like the `.tgz` spelling always did.
- **Encoding detection honours `LoaderSettings`** — every `detect_encoding` call site now passes the loader's settings; `max_disk_bytes` and the chardet tunables were silently model defaults, and the size error told the operator to raise a setting that had already been raised.
- **The vision finalizer's terminality guard is row-based, not counter-based**, so a crash between the page-row update and the counter bump no longer strands the job; vision page retry counters can no longer drift, and vision PNGs survive a failed resume pass.
- **A pause landing on a vision handler is honoured** — the page and finalize handlers now carry the pause guard the other five source handlers already had, the pause evaluator refuses to resume on a foreign witness, and `SystemPauseStatusResponse` reports `paused_by`.
- **A cancelled workflow finalizes its execution row**, and the offloaded chunk-progress increment is shielded from cancellation so a cancel delivered mid-write cannot leave the counter short.
- **Relationship justifications no longer store the model thinking out loud** — a graph edge could carry a "justification" that was deliberation rather than evidence (one `parent_of` edge at confidence 0.9 explained itself with "I will link 9 to 3 via `interacts_with`"). Justifications are now blanked when they carry reasoning markers and otherwise trimmed to two sentences on a sentence or word boundary, so no fragment survives.
- **A `pending_search_index` row with an unhandled `kind` now ages out** — the sweep's unknown-kind branch skipped the row without touching `attempts`, so the `max_attempts` eviction could never fire; the row occupied a batch slot on every pass and kept its source pinned at `degraded`. It now takes the ordinary failure path: the warning stays, `attempts` and `last_error` advance, and the row is retired at `max_attempts`. Latent today (nothing enqueues the documented `template` kind yet), reported as public issue #29.
- **Every configured trigger filter evaluated as "match everything"** — `list_triggers` deferred the `filters` and `actions` columns the dispatcher reads, so a trigger scoped to one source fired on every source; the `.ccx` exporter and `GET /workflows/{id}/triggers` were silently losing the same keys. The columns are projected back.
- **The queue reset promised cancellation and delivered dead letters** — the reset path deleted task hashes without raising the cooperative cancel flag, so a running task re-created a partial hash and landed in the dead-letter set instead of stopping. Reset now runs `cancel_all_tasks` first.

##### Reliability

- **`POST /queue/cancel-all` could freeze the API for the duration of the request** — every cancel path ran a synchronous connect → SELECT → commit → disconnect (with a busy-retry sleep under writer contention) bare on the event loop, once per task. #### v0.4.2 (2026-09-08)

A second fixes-only patch release — 61 commits since v0.4.1. No new features, no
breaking API changes, no schema migrations. Security hardening, queue and chat
reliability, multi-container deployment repairs, and a large reduction in the
work the API does per poll dominate — and live chat streaming, broken since the

##### Security

- **A queued task could create SQLite files at an attacker-chosen path** — `metadata.database_name` on `POST /api/v1/queue/tasks` reached a bare `Path` join in `get_db_path`, which then `mkdir`'d and created a database file wherever the value pointed. The sink now enforces the same `[A-Za-z0-9_-]+` fullmatch that `BackupService` and the queue handlers already applied, which covers every reader of that metadata field at once.
- **The health endpoint was an unthrottled bcrypt oracle** — `location = /api/v1/health` was the one `auth_request` location in the nginx templates without a `limit_req`, so an unauthenticated host on your LAN could drive one bcrypt (cost 12) per stored API key per request. It now carries the same rate limit as its siblings.
- **Per-IP auth rate limiting now enforces the policy it declares** — two halves of one broken control. `proxy-public.conf` blanked `X-Auth-Edge-Token` on exactly the public auth routes, collapsing the app layer's per-IP login and setup buckets into a single global bucket keyed to the nginx loopback peer, so any host on your network could starve the operator's own login (an availability problem, not an auth bypass — `X-Auth-User` was never trusted from outside). And the nginx `auth` zone rendered `login_max_requests` as **requests per second** — 60× the configured per-window policy — while every `*_window_seconds` setting was silently ignored and `setup_max_requests` never rendered at all, because both locations shared one zone. Zones now render as floored requests-per-minute, `/setup` gets its own zone, and burst scales with the per-window count.
- **A settings PATCH could brick every subsequent boot** — `allowed_origins: ["*"]` together with `allow_credentials: true` persisted happily through the settings API and then made `create_app` `SystemExit` on every start, with no API path back in. The pair is now rejected at validation time with a 422.
- **MCP read mode no longer leaks write tools** — five bridge handlers (`summarize`, `research_topic`, and three siblings) were absent from `TOOL_DEFINITIONS`, so in read mode they fell through to `bridge.execute` instead of being refused. The gate is now an allowlist derived from `get_tools_for_mode("read")`. Separately, `chaoscypher mcp --mode read` combined with the maintenance path silently dropped the flag while leaving `apply_upgrade` exposed; that combination now fails before the stdio handshake.
- **Archive ingest enforces volume caps at the function boundary** — `extract_archive()` gained the member-count, declared-total, and streamed-byte limits that `ArchiveExtractor` already applied. Untrusted archives reach this path directly (hub downloads, local `.ccx` files), so the caps now sit where the untrusted input lands rather than only on one caller.
- **Credentials-file updates are serialized across processes** — mutators take a blocking lock on a `credentials.json.lock` sidecar in addition to the in-process lock. With `uvicorn_workers > 1`, a per-request `touch_api_key` rewrite could clobber a concurrent `bump_session_epoch`, leaving a cookie you had just logged out valid until its TTL expired.
- **Dependency advisories cleared** — `pypdf`, `transformers`, and `browserslist` (in both the interface and docs trees) bumped to their fixed versions; `qs` (GHSA-x5fp-wj9c-mxmx, GHSA-4mjr-xmp4-gh2g), `@humanfs/node` (GHSA-p498-v437-472g), and `fflate` (GHSA-px8p-9vwx-vf98) cleared in the interface's development tree, and `qs` pinned in the docs tree, where no bump had been proposed; `js-yaml` (GHSA-2883-xcg3-v3hh, both trees) and `svgo` (GHSA-w27v-7q3p-w38r, GHSA-4vpr-x523-8j87, docs tree) bumped the day they were published; plus the routine interface dependency group updates.

##### Data correctness

- **A task failing before handler dispatch was silently lost** — the queue worker's outer `try` had no `except`, the done-callback never retrieved the task exception, and the `finally` removed the task from the `running` set while its hash still read `queued`. The task existed in neither pending nor running, so it was invisible to the reconciler and to rehydration: it simply never ran and never reported. Such a task is now marked failed-terminal (visible and dead-lettered) and the poller logs the exception through the canonical path.
- **A search-index sweep could clobber a permanently failed source back to `indexed`** — the exhaustion branch deletes its queue row before marking the source failed, so a sibling draining later in the same batch saw zero survivors and flipped the source to `indexed`, hiding a source that would never be searchable. Both indexed-flip sites now refuse to overwrite the terminal `failed` status.
- **Plain chat send was the only turn-enqueue path without the double-enqueue guard** — `/retry`, `/regenerate`, and the edit-resend branch all carry the compare-and-swap claim, with comments naming this exact defect; the plain-send branch still had a blind status write. The claim is now hoisted ahead of message persistence, so the losing request does not leave an orphan user row.
- **Confirming a source with a forced domain could extract under the wrong one** — `forced_domain` and other non-`None` overrides were written in a second transaction after the atomic claim, and `gate_decision` short-circuits on the claim timestamp alone. An import analysis snapshotting inside that window saw a confirmed-but-domainless source and extracted with the auto-detected domain instead of the one you chose. Everything now rides the single write-once claim.
- **The stuck-chat sweeper could stamp an error over a completed answer** — it flipped status from a stale snapshot; it now uses a compare-and-swap mirroring the processing claim, so a worker finishing mid-sweep keeps its result.
- **A pause landing mid-tick was relabelled and later auto-lifted** — the two evaluators share one row, so a user pause arriving during a health tick was re-attributed to `health_monitor` and then auto-resumed. Pause writes are now compare-and-swap guarded, and a probe crossing the trip threshold while the system is already auto-paused joins the witness set with the reason re-persisted, so auto-resume no longer fires into a still-degraded system.
- **Vision page retry counters can no longer drift permanently** — a double decrement made `completed + failed < total_pages` a permanent state; the reset now rides a guarded compare-and-swap. A separate race between a retry and a scheduled finalize is closed too.
- **`reset_all()` leaves a usable schema behind** — a filesystem failure in the destructive section left the application pointed at a schema that no longer existed until someone restarted it by hand. The reset now best-effort reinitializes the schema before the original exception propagates.
- **Resetting the knowledge base can no longer leave you with zero templates** — the template delete commits before the default-template seed runs, so a seed failure left an empty template set behind a generic failed task. The seed retries once and otherwise raises a typed error naming the recovery.
- **`enable_normalization` in the MCP `add_document` schema no longer lies** — the schema advertised a `true` default while the handler defaults to the tri-state `None` (auto: structured formats opt out). A client trusting the schema re-introduced the whitespace-stripping corruption the tri-state was added to fix.
- **The migration lock file is no longer unlinked while a waiter holds it** — `flock` binds to the inode, so removing `.upgrade.lock` for tidiness let a third process lock a fresh inode and run backup-and-upgrade concurrently with an in-flight upgrade. The MCP stdio path, which has no outer init lock, was the exposed caller.

##### Reliability

- **Live chat streaming works again** — the middleware that disconnects request-scoped storage adapters ran its teardown as soon as the response *object* existed, before a streaming body had finished. On `GET /chats/{id}/events` the generator's first suspension is the pub/sub subscribe, and the reconcile that follows it hit a just-disconnected adapter, so **every live stream died with `STREAM_INTERNAL_ERROR` before relaying a token** whenever the chat was actually processing. The answer still appeared on reload — the worker had run and persisted the turn — but nothing streamed. The middleware is now pure ASGI and tears down after the whole response is sent, which fixes the class for any streaming endpoint or background task that touches an adapter after the response object is produced. The middleware previously had no tests; it now has seven, two of which fail against the old implementation.
- **A retryable failure no longer aborts an interactive turn the queue then completes** — a transient failure is published as `status="failed"` before the retry path resets it to `queued`. A poll landing in that window raised, ending the turn, while the queue went on to succeed. Readers now give `error_type=transient` failures a bounded grace before raising; terminal transients still raise immediately.
- **A workflow task that exits before its main body no longer leaks its adapter** — the six early-exit paths (validation raises, zero-step return) now disconnect the execution adapter.
- **Queue statistics no longer fabricate a count** — when the stats query failed, the endpoint returned the current page's row count in the documented total field, capped at the page size, so a 2,000-deep backlog reported "50". It now returns `null` for unknown, which the UI already handles.

- **SQLite lock retry logs identify the operation** — every retry and exhaustion line previously read `operation="transaction"` regardless of what was actually retrying.

##### Security

- **Diagnostic exports could leak API keys when JSON logging is enabled** — the diagnostic collector's secret-scrubbing patterns matched only the unquoted form (`api_key=VALUE`, `api_key: VALUE`). With `USE_JSON_LOGGING=true`, structlog renders log lines as JSON and quotes the field name, so `"api_key": "..."`, `"authorization": "Bearer ..."`, and `"token": "..."` slipped through unmasked and were written into the exported bundle. **This is the headline reason to upgrade if you run the multi-container production stack**, which sets `USE_JSON_LOGGING=true` by default — a diagnostic bundle is something you generate specifically to send to someone else. A label carrying a newline plus a fake `SYSTEM:` line could escalate into the instruction channel and, under the default never-ask tool-approval mode, drive an unattended mutating tool call. Names are now sanitized at the single harvest point (control characters stripped, length capped) and the interpolated lists are wrapped in the repo's `<untrusted_document>` fence. Forged closing fence tags inside document content are defanged, and the system prompt now names the fence explicitly.
- **`CHAOSCYPHER_ALLOW_USER_PLUGINS=0` now actually disables user domain plugins** — the kill switch was honoured by the other plugin loaders but not this one, so user-supplied domain plugins were discovered and executed even with discovery switched off. If you set this variable expecting it to hold, it now does.
- **Archive ingest enforces size and file-count caps before inflation** — `tar.gz` inputs are measured on a streaming pass, so a decompression bomb is rejected instead of being expanded first.
- **Secret material is written atomically at `0600`** — the custom-TLS key upload, the session HMAC secret, and the Lexicon OAuth token used write-then-`chmod`, leaving a brief window where the file was readable by other local users. All three now go through one shared atomic-write helper, and the Lexicon config directory's mode is re-applied on every call.
- **A settings PATCH can no longer lock you out permanently** — `local_auth.edge_auth_header` names the nginx→Cortex trust header; it was writable through the settings API, so renaming it made every subsequent request unauthenticated with no way back in. It joins the protected-field list.
- **Custom embedding endpoints are URL-validated** — `EmbeddingSettings.api_base` now carries the same `validate_url_safety` guard as every sibling custom-endpoint setting.
- **Secure-cookie flag follows TLS state** — `cookie_secure` is re-resolved per cookie write and settings are reloaded when TLS configuration changes, instead of being fixed at process start.
- **`settings.yaml` is written atomically at `0600`** — the settings file carries plaintext provider API keys, the edge-auth token, and the queue and supervisor passwords, and it was written at umask permissions (typically world-readable) and only narrowed to `0600` afterwards. It now goes through the same `mkstemp`-based atomic-secret-write helper as the other secret files, so the plaintext never touches disk in a readable mode.
- **`current_database` is format-validated** — the setting was writable via the settings API with no shape check and joins queries as a raw path segment; it now carries a validator, closing a path-injection-shaped hole.

##### Data correctness

- **A busy-database retry could silently discard committed work** — on `SQLITE_BUSY`, the commit retry rolled back and re-applied a snapshot of pending objects; inside `adapter.transaction()` every write has already been flushed, so that snapshot was always empty. The rollback threw the work away, the retry committed nothing, and success was logged. Callers proceeded on that "successful" commit — `delete_source` in particular tore a source apart, removing the search index and file while the SQL rows survived. The retry now re-arms and re-issues the COMMIT that SQLite is still holding open, and raises when it cannot verify that state.
- **A rebound task database could read and write the wrong database file** — the SQLite adapter and graph repository adopted an ambient session without checking it belonged to their own engine, so an adapter rebound to a task's database could silently operate on the surrounding scope's database instead. Symptoms were cross-database data loss on reset, sources stuck pending, and exports reading the wrong database. Both now adopt the ambient session only when its engine matches.
- **The reconciler no longer dispatches a second copy of live work** — its absolute-timeout branch is deliberately heartbeat-blind, and its requeue path refuses only completed/cancelled tasks, so a `running` task reset to `queued` gets claimed by a second worker. Two call sites derived the cutoff from the wrong timeout (Cortex's safety net read the settings default while workers run on the `workers.yaml` override; both worker sites passed their own deadline verbatim, so the cutoff expired at the same instant the worker's did). A single resolver now reads the same override, clamps it with shared policy bounds, floors it at the settings default, and adds a safety margin.
- **Cancelled tasks are not dispatched, and cancellation survives a restart** — the worker's running-claim is now guarded against a task cancelled between claim and dispatch, and `cancel_by_metadata` persists a durable cancellation marker rather than relying on in-flight state alone.
- **Chat retry/regenerate no longer double-enqueues** — status is claimed atomically, and terminal status is reconciled after SSE subscribe via a sentinel, closing the window where a client subscribing late saw a stale non-terminal state.
- **A failed save no longer duplicates chat messages on retry** — message persistence committed one row at a time with no enclosing transaction, so a mid-write failure left earlier rows durable and the retry re-inserted them. The whole batch now commits as one transaction, matching the documented contract.
- **Sources no longer wedge at `vector_indexing_status: pending`** — a failure while enqueuing the search-index retry, after the commit had been marked complete, permanently lost the retry, the degraded mark, and every recovery path. All three enqueue sites are guarded; on failure the source is marked `degraded`, which is recoverable.
- **A source is marked indexed only after its last pending search row drains**, so the indexed state can no longer be reported ahead of the work.
- **Template re-embedding: one bad template no longer poisons the batch, and graph/search can't silently diverge** — each template's work is now isolated and failures are counted rather than forcing a full-batch retry that re-embeds everything already done. The graph-row update and the search-index write also share a single transaction; previously the graph write committed on its own while an index failure was swallowed as a warning, leaving a permanent mismatch with no reconciliation path.
- **Extraction recovery keeps SQLite and the queue in agreement** — when marking a chunk task queued fails after the re-enqueue succeeded, the live queue task is now best-effort cancelled before the error propagates.
- **Vision pages retry instead of being marked failed** — retryable LLM errors from image description are propagated rather than swallowed into a terminal per-page failure.
- **Per-source table rows are scored correctly in quality scoring (v8)** — reference counts and chunk mentions were computed against the wrong source of truth, so quality scores for table-bearing sources were wrong; the Cortex slice, the Neuron recalculation handler, and the CLI now all ride the same canonical helpers and read the per-source extraction tables.
- **Migration backups are recorded before they are needed** — the pre-apply backup path is persisted before the upgrade runs, and `last_backup` survives a successful data-changing apply.
- **A task retry can no longer resurrect a cancelled task** — the retry path blind-wrote `status="queued"` with no compare-and-swap, so a task cancelled while running was revived and executed a second time in full; the reconciler's guards never saw the cancelled state to refuse it. The retry now claims through the same guarded status write as everything else.
- **Switching databases rebinds the system-event bus** — the singleton `event_bus` stayed bound to the previous database's adapter after a switch, silently writing system events into the old database file.
- **Re-importing a CCX package no longer duplicates citations** — import is idempotent on citation rows, matching the upsert-by-IRI behavior nodes and edges already had.

##### Reliability

- **Low-priority LLM work no longer starves** — the admission gate compared total active work against the low-priority allowance instead of the low tier's own counter, so high-priority work consumed the low tier's budget and a low-priority waiter could block forever on an untimed wait. The reserved-interactive slot count is also clamped below `llm_max_concurrent` (matching the UI's own clamp) on load, on live settings reload, and when the maximum alone shrinks. A configuration with `llm_reserved_interactive >= llm_max_concurrent` is now clamped with a warning naming both values rather than starving silently.
- **Databases created before the 2026-06-02 schema squash now refuse startup with guidance instead of failing obscurely** — such a database was re-stamped at the baseline, after which the shipped migrations replayed against a schema they were never written for and the boot died in the drift gate on every supervisor retry. The squash predates every public release, so no released build ever wrote one of these; they are explicitly unsupported. Cortex now exits cleanly with an `UnsupportedDatabaseLineageError` naming the revision and the recovery path (back up, then re-create or export/re-import), and the stamp is left untouched.
- **Queue reconciliation falls back to the canonical queues** when Cortex's reconcile registry is empty, instead of silently reconciling nothing.
- **Blocking work moved off the event loop** — the stuck-chat sweeper's SQLite I/O, the Neuron health-monitor tick (now also inside a session scope), the vision spend-tracker check/record, and the chat status/persist writes all run in threads, matching the offload pattern the surrounding handlers already used.
- **Bulk resume recovers per source** — each recovery in a bulk resume runs in its own adapter session scope, so one failure no longer aborts the rest.
- **Source heartbeats run on their own session** — background beats could execute on the finalize transaction's session from a second thread. Each beat now uses a short-lived session of its own.
- **Upgrade recovery finds its source** — the recovery path reads `source_id` from task metadata, where it actually lives.
- **Cancellation no longer phantom-releases an LLM slot** that a clear-wake had already handed to another waiter.
- **`POST /admin/plugins/reload` actually reloads** — the endpoint cleared a cache map no production code ever populated, returning success while every real registry kept serving stale plugins until a process restart. The loader, domain, and preset registry caches are now registered with the invalidation path — and they are keyed by the resolved plugin root rather than settings-object identity, so per-request settings objects no longer leak one dead registry each.
- **Cortex's health-monitor tick runs in its own session scope** — it shared the process-singleton fallback session with request handlers emitting system events, a not-thread-safe combination whose failure mode was system events silently stopping and auto-pause dying for the life of the process (the Neuron sibling was fixed for exactly this earlier).
- **The Lexicon client no longer leaks connection pools** — download/upload clients were created per request and never closed, and all four `LexiconSettings` knobs (timeouts, retries) were ignored; both fixed.

##### Performance

- **`POST /search/embeddings` batches** — it embedded up to 10,000 nodes one at a time inside the request: one provider round trip, one SELECT+UPDATE+COMMIT, and one single-row vector upsert per node. It now collects the pairs, makes one batched embedding call, and persists in one transaction with a batched index refresh — roughly 156 provider calls for 10,000 nodes at the default batch size instead of 10,000. (Its docstring also no longer claims the work happens in the background; it never did.)
- **CLI `index-file` batches chunk-embedding writes** — one bulk UPDATE and one commit per embedding wave, replacing a full-row SELECT plus a real commit per chunk (a 3 MB import was ~4,000 of each). Resumability is preserved at wave granularity.
- **Search results hydrate faster** — assembling a page of chunk results issued two serial database calls per chunk. Chunks are now fetched in one batched query per page and repeated source lookups are memoized, mirroring how node results already worked. Most noticeable on large result pages.
- **Read paths project only what they use** — chunk-task summaries collapse to one `GROUP BY`, the workflows dashboard replaces per-workflow queries with one aggregate, `update_file`/`update_source_columns` project key columns only, graph-snapshot staleness reads three scalars instead of loading the row's JSON payload, and scoped-chat source titles resolve in one batched call instead of a per-source loop.
- **`GET /sources/{id}/vision_pages` stops shipping every page's LLM description** — the endpoint is polled, and the description text column dominated the payload; `error_message` (which the UI renders) is retained.
- **Chat existence and status checks stop loading 500 message rows** — four `chats` endpoints now use a summary read, and `GET /chats/{id}/messages` no longer reads its messages twice.
- **Chunk-offset matching is no longer quadratic** — exact matching carries a forward cursor and per-chunk location lookups use binary search.
- **Deleting a source batches its orphaned search-index node deletes** instead of one pooled connection and commit per orphan.

##### Interface

- **Light mode is readable again** — the theme swapped `background` on the dark-mode toggle but pinned `text.*` and `divider` to the dark-only slate neutrals unconditionally, so switching to light mode (a live switch in General Settings) rendered near-white text on a near-white background across every component reading the `text.*` token. The slate overrides now apply only in dark mode, with MUI's accessible light defaults otherwise.
- **The Sources status filter is actually applied** — the parameter was accepted but never placed on the outgoing request.
- **The template force-delete dialog can open** — it matched two error-message substrings the API never sends; it now matches the real `409 TEMPLATE_IN_USE` response. The templates empty state also spans the right number of columns.

##### CLI

- **`template get`/`update`/`delete` report a missing template** rather than falling through dead `None` guards, and the help text lists all 13 property types.
- **`quality` commands read the per-source extraction tables**, matching the scoring fix above.
- **`quality recalculate` exits non-zero on failure** — it counted and printed per-source errors but always exited 0, so scripted invocations could not distinguish success from total failure. Old `cc …` command hints in error messages are also corrected to `chaoscypher …`.

##### Docs

- Template docs corrected: CLI examples used names where only IDs resolve, and delete semantics were documented backwards (`force=true` is a cascade delete; a plain delete is blocked, never dangling).
- The upgrading guide and ADR-0006 no longer promise auto-recovery for pre-squash databases.
- **The CCX 3.0 format has a published draft specification** — [`reference/ccx-format`](../reference/ccx-format.md) documents the container, manifest schema, JSON-LD graph members, `sources.jsonl` row schemas, and the validator's conformance classes, written against the shipped `ccx-format` reader.

#### v0.4.0 (2026-08-07)

##### Breaking Changes

- **`GET /sources/{id}/recovery_events` now uses standard pagination.** The endpoint previously took `?limit=` (1–200, default 50) and returned `{"events": [...]}`. It now takes `?page=&page_size=` and returns the house `{data, pagination}` envelope, matching every other list endpoint. **Migration:** replace `?limit=N` with `?page_size=N`, and read events from `data` instead of `events`; the pagination block is `{total, page, page_size, total_pages, has_next, has_prev}`. `?limit=` is no longer read. The web UI ships already migrated, so the product is self-consistent — this affects external API consumers only. (Pre-1.0 convention: breaking changes ride MINOR; `0.y.z` carries no compatibility guarantee.)

##### Security

- **Compose package resolver could be made to write outside its extraction directory** — the resolver built its extraction path from the Lexicon hub's own `version` string, so a hostile or compromised hub could place package contents anywhere the process could reach, including the auto-executed user-plugin directory. Path construction is now hardened. The same fix corrects shifted client arguments that had made hub resolution unable to match any package, so no working behavior regresses.
- **`cryptography` 48.0.1 → 50.0.0** — CVE-2026-69247, CVE-2026-69248, CVE-2026-69249. 50.0.0 is the minimal clearing version (69247 does not clear below it).
- **URL import no longer has a DNS-rebinding window.** `POST /api/v1/sources/url` validated each hop and then handed the *hostname* back to the HTTP client, which re-resolved it at connect time — so a name that resolved to a public address during the check could resolve to an internal one for the actual fetch. The fetch now dials the validated IP directly, carrying the original `Host` header and TLS SNI, and redirect targets are re-validated the same way. Earlier releases documented this as an accepted residual in the self-hosted threat model; that entry is gone because the residual is.
- **`pypdf` ×6 CVEs cleared** — ×4 earlier in this cycle, plus CVE-2026-71852 and CVE-2026-71870 in `pypdf 6.14.2`, cleared by 6.15.0 on the day they were published. PDF parsing is an attacker-reachable surface for anyone ingesting untrusted PDFs, so this is the highest-value dependency fix in the release.
- **`js-yaml` CVE-2026-59870** cleared (4.3.1).
- **Further dependency advisories cleared** — `pyasn1`, `fast-uri`, `brace-expansion`, `react-router`, `js-yaml` (via redocly), `nanoid`, `dompurify`, `mermaid`, every other `packages/docs` npm advisory, and `undici` / `ip-address` in the frontend toolchain. `pip-audit` and both `npm audit` runs report clean, and the documentation site's dependencies are now covered by the CI security gate.
- **Self-signed TLS key is created with `0600` from the start** — previously it was briefly world-readable on disk.
- **Typed local-auth errors** for a corrupt password hash and for double-initialize, instead of opaque failures.

##### Data correctness

- **`load_text` silently dropped every document after the first** — multi-document loads were losing content with no error surfaced.
- **Backup restore could lose recent commits.** The restore path unlinked the live WAL/SHM and overwrote `app.db` *before* disposing cached engines, and its "safety backup" was a WAL-blind file copy — so recent committed data could vanish on a restore. Restore now mirrors the upgrade-rollback path and takes its safety copy with `VACUUM INTO`.
- **`env > settings.yaml` precedence restored** — a regression had stopped environment variables from winning.
- **Races that produced duplicate or lost work are closed** — `confirm_extraction` and `retry_task` claim via SQL compare-and-set; queue cancellation and reconciler paths are atomic under a lock; chat tool-approval is first-decision-wins.
- **`StageProgress` no longer reports a stage complete when its body raised.**
- **A failure *after* a chunk was committed no longer discards its extracted entities.** Everything following the chunk-persist commit sat inside the same `try`, so a late failure (for example a full finalize queue) marked an already-committed chunk `failed` — and because the finalizer aggregates only `completed` rows, the entities you had already paid to extract were silently dropped. The post-commit tail is now guarded and the row stays `completed`.
- **Archive and RST ingest fixes** — three P1 defects in the archive/RST loader paths and in force-re-extract.
- PDF image-detection scans are capped at `pdf_max_pages`; workflow-system reset is atomic and reports real deleted counts; chunk-pipeline handlers honour the task's target database.

##### Reliability

- **One call to `DELETE /llm/semaphore` could wedge all LLM traffic for the process lifetime** — `PrioritySemaphore.clear_waiting_queues()` awaited a helper that re-acquired its own non-reentrant lock, deadlocking on itself. A related path leaked a concurrency slot permanently when an exception escaped the worker's cleanup block.
- **MCP extraction hardening** — finalize now rolls back cleanly on failure, quick-depth is forwarded correctly, and a session leak is evicted rather than accumulating.
- Deep audit passes over the chat and queue slices fixed a batch of defects each: citation-grammar alignment and contentless-done refetch in chat; worker-cleanup semaphore leak, swallowed-timeout-as-cancelled, sub-cent LLM cost truncation, and several queue-monitor UI defects.
- **Workflows slice audit — the automation path had four defects that made it unusable in places.** `ai.extract_json` always failed with "Engine settings not provided" and `ai.prompt` silently fell back to hardcoded defaults, because settings were never threaded into the tool context. Queued step execution died with a `TypeError` from an orchestrator/executor signature mismatch hidden behind two `type: ignore`s. Imported or duplicated workflows were stored with an empty database name, so they never appeared in any list. And `summarize` lost every page beyond the first for all sources after the first. Also fixed here: explicit `temperature=0.0` and `chunk_overlap=0` are honoured instead of being replaced by defaults, malformed fenced JSON from a model falls back to text instead of raising, trigger stats no longer grow without bound in the long-lived executor, and CrossEncoder construction is moved off the event loop.
- **Speed-ups on the paths that dominate large imports** — chunk-embedding persistence went from one full-row `SELECT` plus one real `COMMIT` per chunk (up to 2,000 per wave) to a single batched update; the vision finalizer no longer rebuilds the whole document body once per page description; package-import citation writes and workflow-execution listings use the batch primitives that already existed alongside them.
- **Failures stop being invisible** — search-index flag reads log instead of silently returning `false` during the contention they exist to guard, and a close failure while recording spend no longer masks a permanent spend-cap error into one the queue retries forever.

##### Features

- **Per-call extraction overrides now actually take effect.** The source-creation API accepted per-call extraction settings and then ignored them, falling back to the global configuration; the values you pass are now applied to that source's extraction.
- **`chaoscypher source list --limit`** with an honest truncation footer, and **`config set`** now accepts list-valued settings.

- **Guarded-write / atomic-move primitives** on the queue client (internal substrate for the correctness fixes above).

- **`0006_loader_epub_chapters_skipped`** — additive only (one new quality-counter column), classified `safe_auto`, so it applies on startup with automatic migrations enabled (the default). No destructive operations.

### May 2026

- **Universal LLM stage progress facility** — Per-page, per-batch, and per-chunk progress for every LLM-bound stage of the import pipeline (vision, embedding, MCP extraction) now flows through a single `StageProgress` async context manager backed by a new `llm_stage_progress` table (now part of the consolidated `0001` baseline migration). Each stage row carries an exponentially-weighted moving average (`avg_ms`) of milliseconds-per-item; the UI converts it into a live `X/Y items · ~remaining` estimate that ticks every page. Replaces three previously-divergent timing sources (queue stats, a hardcoded size/chunk/entity heuristic, a legacy MCP-only EMA service) with one source of truth — both the per-row top-right slot and the "Processing Documents" header now read the same number. The six legacy `extraction_chunks_*` columns were dropped at the same time; CC-049 blocks their re-introduction.
- **40 quality counters (up from 18)** — The quality-counter view (now the **Pipeline flow** section on the source’s Overview tab) surfaces every silent-drop / silent-merge / silent-skip site in the pipeline, including 22 counters previously not allowlisted at the adapter layer (so increments were silently rejected). The SQLite adapter now derives its allowlist from the `QualityCounter` enum so adding a new counter is sufficient; a drift test pins the relationship. New stage section: Embedding (chunk failures, dimension mismatches). Two counters (`loader_html_dropped_tags`, `loader_pptx_shapes_skipped`) are JSON-shaped per-key breakdowns rather than scalars.
- **Large PDF uploads (>1MB)** — nginx's auth_request subrequest no longer inherits the server-level `client_max_body_size`; the per-route override applies to the auth check too. Restriction-only "encrypted" PDFs (Adobe Acrobat output, OCR scans, journal articles where encryption only signals permission restrictions) now load normally — the PDF loader attempts an empty-password decrypt before raising `EncryptedPDFError`. Frontend translates 413 responses to a size-specific message rather than the generic "server error" copy.
- **Chunker coalesces short chunks** — The `min_chunk_size` filter no longer drops sub-threshold chunks. It now coalesces them with a neighbor (merging into the next chunk that lifts the combination over the threshold) so natural-prose imports — dialogue, transitions, short paragraphs — keep all content reaching extraction. Fixes a W5 data-loss regression observed on `war_and_peace.txt`, where 80 chunks of real Tolstoy prose were being silently discarded. Default `min_chunk_size` lowered from 500 to 100 to keep the merging gentle on natural prose. The renamed `chunks_coalesced_count` counter (and the "Chunks coalesced" tile in the Pipeline flow section) now records merge events, not drops.
- **Upload-settings persistence** — Every choice you make at upload time (`auto_analyze`, `enable_normalization`, `enable_vision`, `content_filtering`, `filtering_mode`) is now a real column on the source row. Recovery, retry, and re-extract reuse what you set without you having to re-pass it.
- **Pipeline flow quality counters** — Every silent-drop site in the pipeline (loader / cleaner / chunking / LLM / post-extraction / commit) now increments a typed counter on the source row. The Pipeline flow section on the source detail page’s Overview tab surfaces every counter with plain-English explanations, distinct from the existing Quality grade. Counters reset on Re-extract so you can compare runs.
- **Filtering modes 0–5 redesigned** — The slider now produces distinct results at every level. Three previously-dead settings (`loop_max_entity_count`, `semantic_dedup_threshold`, `minimum_alias_length`) are now wired so each preset (`unfiltered` / `minimal` / `lenient` / `balanced` / `strict` / `maximum`) tunes the pipeline differently. Plain-English documentation at [Filtering Modes](../reference/filtering-modes.md).
- **Production extraction parity** — Cortex, the standalone CLI, and the MCP path all share one post-extraction helper (`apply_structural_and_normalization`). The same source produces the same graph regardless of which entry point ran the extraction.
- **Normalization & chunking honesty** — Operator's `NormalizerSettings` now actually reach the cleaners (was silently ignored). `min_chunk_size` / `max_chunk_size` / `respect_boundaries` are wired through to the splitter. Zero-chunk sources raise `ValidationError` with an actionable hint instead of committing silently. The OCR cleaner is scoped to OCR-derived content via `applies_to(metadata)` so short identifiers like `git` / `npm` / `K8s` survive on plain text and HTML.
- **Loader correctness** — Shared `detect_encoding()` helper for all text-shaped loaders (UTF-8 strict → cp1252 strict → charset-normalizer → Latin-1, no silent `errors="replace"`). JSONL parsed line-by-line with per-line error isolation. CSV uses a dialect sniffer. Scanned-PDF specific errors. `application/octet-stream` removed from the default upload allowlist (operators who need it can opt back in).
- **6 new built-in loaders** — HTML, RST, DOCX, XLSX, PPTX, EPUB. EPUB hand-rolled to avoid taking on an AGPL `ebooklib` dependency.
- **LLM observability** — `finish_reason` populated by all 4 providers (Ollama, OpenAI, Anthropic, Gemini) and normalized to a stable vocabulary (`stop` / `length` / `content_filter` / `tool_calls` / `error` / `unknown`). Streaming line-buffer flushes the trailing partial line so the last entity isn't silently dropped. Chunk-level `finish_reason` and `aborted_by_loop` surface on the extraction-task API; chunk truncation and abort counters surface on the source row.
- **Upload contract hardening** — URL fetcher validates the upstream `Content-Type` against the allowlist, honors any `charset=…` parameter, and routes binary responses through the binary loader path. CLI fully matches the API contract: `--vision/--no-vision`, `--content-filtering/--no-content-filtering`, `--normalize/--no-normalize`, `--filtering-mode`, `--skip-duplicates`.
- **Vector search visibility** — `vector_indexing_status` field with four states (`pending`, `indexed`, `degraded`, `failed`). New `SearchStatusBadge` UI component on the source list and detail page. The orphan-sweep worker drives `degraded` → `indexed` retry and `degraded` → `failed` retry-exhaustion.
